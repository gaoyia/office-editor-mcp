# 位置 id 第二期：docx 表格行列

状态：❌ 未开始。
日期：2026-10-30

不在三种格式的待做表里，不占待做序号。前置：「位置id第二期-机制与覆盖表」已完成。

## 为什么先做这一份

表格行列是同一批里最容易漂移的：先 `insertRow` 再给后面的格子写字，或者先 `deleteCol` 再合并单元格，都是很自然的一批 op。现在后面的 op 会落到错一行或错一列的格子上。

## 范围

- 表：`table:{n}`，以及页眉页脚、框内的 `{容器 id}/table:{n}`
- 行：`table:{n}/row:{r}`
- 格：`table:{n}/r{r}c{c}`
- 会让它们重排的 op：`insertTable`、`deleteTable`、`insertRow`、`deleteRow`、`insertCol`、`deleteCol`、`mergeCells`，以及插删段落时连带删掉整张表的情况

## 不做

- 不改合并单元格的语义：`gridSpan` / `vMerge` 后被吞掉的格子，按现有契约处理。
- 注内、批注内的表本期不支持编辑，不在范围里。

### 1. 文档

在 `docs/json-contract-docx.md` 的表格 id 一节写明：

- 一次 apply 里，`table:{n}`、`row:{r}`、`r{r}c{c}` 都按 apply 开始时的表解释。
- 本批插入的行和列不占旧编号，要等下一次 inspect。
- 被删掉的行、列或表，后面再点名报 `IdNotFound`。
- 合并之后被吞掉的格子，再点名时的行为写清楚。

### 2–3. 实现

- 用通用机制给 `w:tbl`、`w:tr`、`w:tc` 编号。列号按 apply 开始时的网格列算，`gridSpan` 的处理在文档里先定好。
- 把 `docx/tbl.rs` 里按下标数表、数行、数格的地方逐个改走编号查找。先列清单，写回本节，再改。

### 4. 测试

每种结构类 op 都要有一条「先增删、再点名原对象」的测试：

- 先 `insertRow` 在第 1 行后插一行，再写原来第 3 行的格子，改到的是原来那一行。
- 先 `deleteCol` 删第 1 列，再写原来第 3 列的格子。
- 先 `deleteRow`，再点名被删的行，报 `IdNotFound`。
- 先 `insertTable`，再点名原来的 `table:2`。
- 框内的表、页眉页脚里的表各一条。

在覆盖表里把这些 op 从「待第二期」改成对应的测试名。

### 5. 手测

用 Word 16.0 打开「先插行、再写原第 3 行」和「先删列、再合并」两份产物：表格结构正确，字写在预期的格子里，不报修复。
