# WASM 宿主边界

状态：⚠️ 前两轮已落地，第三轮未做
日期：2026-10-24

不在 `roadmap/docx.md`、`roadmap/xlsx.md`、`roadmap/pptx.md` 的待做表里。这是用户点名的架构整理，不占待做序号。领域 JSON 不改，命令行仍接收路径。

契约真源仍是 `docs/`。本切片要补的是 `docs/architecture.md` 里库和宿主的边界，不是新的操作字段。

## 目标

`crates/ooxp` 只处理内存里的 ZIP。打开文件、保存文件、按路径读图片和嵌入物、取随机数、取时间、取进程号，都由调用方做。命令行行为与现在相同。库能用 `wasm32-unknown-unknown` 编过。

## 不做

- 不改 `inspect`、`apply`、`create`、`help` 的领域 JSON。
- 不把命令行编进 WASM。
- 不写渲染引擎，不把 `office_oxide` 写进 `Cargo.toml`。
- 不在这一份里做 Electron 窗口。

## 三轮

| 序号 | 项 | 状态 |
| --- | --- | --- |
| 1 | 门口只收字节、交字节 | ✅ |
| 2 | 插文件改为由调用方读字节 | ✅ |
| 3 | 随机数、时间、进程号由调用方传入，并编过 WASM | ❌ |

三轮串行。上一轮的现有测试过了，才开下一轮。每轮先改 `docs/architecture.md`，再改代码。

### 1. 门口

`dispatch::run` 今天按 JSON 里的 `path` 自己 `std::fs::read`，写回时走 `write_atomic`。

这一轮改成：库的入口接收已经读好的字节，返回新的字节。命令行负责读路径、写路径，JSON 里的 `path` 仍由命令行解释。`inspect`、`apply`、`create`、`help` 在不碰磁盘的调用里能跑。`exportMedia` 和 `exportChartData` 同样由调用方拿到字节再落盘。

出口：现有命令行测试仍通过。用字节调用 `inspect` 和 `apply` 的路径不再出现在库门口。

### 2. 插文件

这些操作今天在库里按路径 `std::fs::read`：图、音视频、OLE、墨迹、3D 模型、嵌入字体。位置在三种格式的 picture、ole、ink、media，以及 `model3d.rs`、`font_embed.rs`、`timing.rs`、`transition.rs`。

这一轮改成同一套读字节的入口。JSON 里继续写路径。命令行见到路径就读完再交给库。库内不再调用 `std::fs::read` 去打开用户给的文件。

出口：现有插图、插 OLE、插墨迹、插 3D、嵌字体的测试仍通过，只是读文件发生在命令行一侧。

### 3. 随机数和时间

`getrandom` 用在保护、书目、术语表和嵌入字体。`SystemTime::now` 和 `std::process::id` 用在批注、幻灯片节、自定义视图和 SmartArt，用来拼 id。

这一轮改成由调用方传入随机数、时间和进程号。命令行仍用本机的这三项，所以现有文件里的 id 算法不变。然后执行：

`cargo build -p ooxp --lib --target wasm32-unknown-unknown`

编过即本轮完成。编不过就只补 WASM 目标缺的宿主接口，不改领域行为。

- `cargo test -p ooxp` 通过。
- `cargo build -p ooxp --lib --target wasm32-unknown-unknown` 通过。
