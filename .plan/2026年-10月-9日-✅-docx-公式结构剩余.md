## 目标

## 探测结论

COM `OMaths.Add` 返回 Range，不能对 Add 结果设 `Type`。先写线性字、`MoveEnd` 去掉段落标记，再 `Add`，然后 `OMaths.Item(1).BuildUp()`。`a/b` 写出 `m:oMathPara` / `m:f`。手写最小 OMML（不写 `rPr` / `ctrlPr`）打进 create 产物后，Word 16.0 打开无 Repair，另存不改结构。已验证 frac、rad（`degHide`）、cbrt、sSup、sSub、nary（`chr=∑`）、delim、func、mat、acc、嵌套 `(a/b)^2`。

## 契约（已锁）

- 只认顶层 `m:oMath`。嵌套对象走 `expr`，不再另编 id。
- 每条公式字段顺序：`id`、`index`、`kind`、`host`、`text`、`expr`。`text` 仍是子孙 `m:t` 拼接。`scope.maths` 为 true 才有名单。
- `expr` 是数组，对应 `oMath` 的直接子元素顺序。inspect 忽略 `m:*Pr`、`ctrlPr`、`m:rPr`、`w:rPr`。
- 节点 `type`：`text`、`frac`、`rad`、`sSub`、`sSup`、`sSubSup`、`sPre`、`nary`、`delim`（`m:d`）、`func`、`mat`（`m:m`）、`acc`、`bar`、`limLow`、`limUpp`、`eqArr`。其余 inspect 为 `other`（`name` + 拼接 `text`）。apply / create 写 `other` 报 `InvalidField`。
- 槽都是节点数组。`frac`：`num` / `den`，可选 `fracType`：`bar`（缺省，不写 `fPr`）/ `skw` / `lin` / `noBar`。`rad`：`e`；平方根 `degHide: true` 且不要 `deg`；`degHide` 与有内容的 `deg` 同时给报 `MutuallyExclusive`。`nary`：`e`；可选 `chr` / `sub` / `sup`；省略 `chr` 不写 `naryPr`。`delim`：`args` 至少一组。`mat`：`rows[]` 每项 `{ "cells": [ 节点数组, … ] }`，各行列数相同。`func`：`fName`、`e`。
- `insertMath` / `setMath` / `paragraphs[].maths[]`：`text` 与 `expr` 恰好一个。只有 `text` 时行为与 21 相同。给了 `expr` 按树写/替换，不改 `kind`，不拆 `oMathPara`。
- 空 `expr`、空必填槽、不认识的 `type`、同时给 `text` 与 `expr`、两个都不给，报 `InvalidField`。出现 `tex` / `unicodemath` / `omml` 报未知字段。
- 仍不写：框内 / 注内 / 批注内公式、Equation Editor 3.0 OLE、run 样式 op。`box` / `borderBox` / `phant` / `groupChr` 只 inspect 为 `other`。写最小 OMML，不写 `m:rPr` / `ctrlPr`。

## 不做

- 公式排版引擎、与 Word 像素级一致
- 把线性字解析成分数
- 旧式 OLE 公式
- 任意 OMML 属性全集（对齐、断行、幻影、边框盒本期不写，inspect 进 `other`）
