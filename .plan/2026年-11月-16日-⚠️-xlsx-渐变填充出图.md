## 机制（SpreadsheetML ≠ DrawingML/PPT）

- OOXML `CT_GradientFill`：`type` 缺省/`linear`，`degree` 缺省 0，`stop/@position` + `color`。`path` 与 left/right/top/bottom 收敛本刀 **NI**。
- 官方文字：degree 0=左→右（竖条），90=上→下（横条）；与 ECMA-376 / MS Open XML `GradientFill.Degree` 示例一致。
- 独立样本 `manual-check/office/out/xlsx-gradfill-probe.xlsx`：两格 FF92D050→FF0070C0，degree 缺省与 90；Excel 保存后 styles 仍为 `gradientFill`（非 pattern）。
- **插值**：Excel `ExportAsFixedFormat` PDF 以细条近似渐变，端点恰为停点色；全条 RMSE(sRGB lerp)≈0.68，RMSE(gamma 2.2)≈18.5。故单元格走通道直线 `mix`（与 colorScale 同），**绝不**复用 PPT `fill_gradient`/`gamma_mix`。CopyPicture 金样同样从近停点色起坡（首可见像素≈(144,207,82) 而非精确 (146,208,80)），与 lib 在 96dpi 格子坐标（含左上外框格点后再被 leading frame 盖白）一致量级。
- theme / indexed / auto / tint / A≠FF / 多于两停 / `type=path` → `Fill::Nope` → 整表 `NotImplemented`。

## 手测（Asia/Shanghai）

- 金样门：`Range.CopyPicture` xlScreen/xlBitmap → `xlsx-gradfill-probe-gold.png` **203×60**（~106dpi）。
- lib CLI `exportSheetImage` → `xlsx-gradfill-probe-lib.png` **177×54**（96dpi MDW 列宽）。**sizeDiffer → pxBlocked**；不改金样、不放宽容差、不缩 DPI。列宽残差归 MDW/DPI，不全怪本刀渐变。
- PDF 仅作颜色/方向辅助证据，**不能**替换 CopyPicture 金样原门；CLI 出图 ≠ layout PASS。
- 等线行高：COM 矩阵 10/11/空/StandardHeight=14.25；12=15.75；18=23。代码锁 **11→14.25**；其它字号 `pt*15/11`。不回归 Calibri11=15、雅黑 1.65×。
