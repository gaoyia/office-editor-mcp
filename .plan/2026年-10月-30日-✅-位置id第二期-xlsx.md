# 位置 id 第二期：xlsx

状态：✅ 已完成。
日期：2026-10-30

不在三种格式的待做表里，不占待做序号。前置：「位置id第二期-机制与覆盖表」已完成。

单元格 id（`cell:{sheet}!A1`）和工作表 id（`sheet:{name}`）按内容编号，不漂移，不在范围里。

## 范围

- 表内名单：`dv:{n}`、`cf:{n}`、`table:{n}`、`pivot:{n}`、`link:{n}`、`spark:{n}`、`editRange:{n}`
- 工作簿名单：`name:{n}`、`customView:{n}`、`cellStyle:{n}`、`extlink:{n}`、`connection:index:{k}`
- drawing 对象没有 `cNvPr/@id` 时的退路：`pic:index:{k}`、`chart:index:{k}`、`sp:index:{k}`、`shape:index:{k}`、`cxn:index:{k}`、`math:index:{k}`、`smartdiagram:index:{k}`、`ole:index:{k}`、`model3d:index:{k}`、`slicer:index:{k}`，以及页眉页脚图
- 趋势线和误差线归「位置id第二期-图表趋势线误差线」

会让它们重排的 op：上面各族自己的 `insert*` / `delete*`，以及 `deleteSheet`（连带删掉表内名单）、`groupShapes`、`ungroup`。

## 不做

- 不改公式里对定义名的引用，不求值。
- 不处理 `insertSheet` / `moveSheet` 对工作表名的影响，工作表按名字点名。

### 1. 盘点

编号在 apply 开始、第一次读到部件时写下。新建的接在已有对象后面，不另记空编号；旧编号先被认走，不会落到新建的对象上。

- `dv:{n}`：工作表 `dataValidations/dataValidation`。`validation::nth_mut`
- `cf:{n}`：工作表里各 `conditionalFormatting/cfRule`，按文档顺序连着数。`cf::find_rule`
- `link:{n}`：工作表 `hyperlinks/hyperlink`。`hyperlink::nth`
- `spark:{n}`：工作表 `extLst` 里迷你图 `sparklineGroup`。`sparkline::find_path`
- `editRange:{n}`：工作表 `protectedRanges/protectedRange`。`protect::nth_range`
- `table:{n}`：工作表 `tableParts/tablePart`。`table::apply_delete` / `append_tables_from`
- `pivot:{n}`：工作表关系里的数据透视表，apply 开始时记下关系 id。`pivot::pivot_part_at`
- `name:{n}`：工作簿 `definedNames/definedName`。`names::defined_name_at`
- `customView:{n}`：工作簿 `customWorkbookViews/customWorkbookView`。`custom_view::nth_guid`
- `cellStyle:{n}`：样式部件 `cellStyles/cellStyle`。`style::delete_cell_style`
- `extlink:{n}`：工作簿 `externalReferences/externalReference`。`extlink::delete`
- `connection:index:{k}`：`connections.xml` 里没有 `id` 的 `connection`。`connection::delete`
- drawing 的 `:index:{k}`：apply 开始时按 inspect 的顺序跨部件累加，记在对象上。图、图表、文本框、形状、连接线、公式、SmartArt、切片器走锚点；三维模型和墨迹走各自的收集顺序。页眉页脚图按槽分开。查找仍是原来的 `key_matches`，序号改认这个编号

### 2. 文档

在 `docs/json-contract-xlsx.md`「稳定 id」写明：一次 apply 里这些编号按开始时解释；本批新建的不占旧编号；被删掉的再点名报 `IdNotFound`。

### 3–5. 实现

分三步，每步跑一次 xlsx 测试：先做表内名单，再做工作簿名单，最后做 drawing 退路。

### 6. 测试

- 每族一条「先删前面一个，再改原来的第 n 个」。例如先 `deleteDataValidation dv:1`，再 `setDataValidation dv:3`，改到的是原来的第三条。
- 定义名多一条：先 `insertDefinedName`，再改原来的 `name:2`。
- drawing 退路的样本要去掉 `cNvPr/@id`，用手写的 XML。

回归在 `crates/ooxp/tests/xlsx_id_pin.rs`。数据验证、条件格式、定义名、超链接、迷你图、保护区域、表和图各有一条。其余族走同一套编号，覆盖表写「入口同」。

### 7. 手测

用 Excel 16.0 打开「先删第一条数据验证、再改原来第三条」与「先删第一条条件格式、再改原来第二条」两份产物，改动落在预期的规则上，不报修复。
