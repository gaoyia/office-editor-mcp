## 探测结论（Word 16.0）

- `Fields.Add`：PAGE 为复杂域；NUMPAGES / FILENAME / DATE / TIME / AUTHOR / MERGEFIELD 另存常写成 `w:fldSimple`；LISTNUM=90、DOCPROPERTY=85 为复杂域。指令常带 `\* MERGEFORMAT`。库继续写复杂域 + `w:dirty`、不写 MERGEFORMAT；PAGE 已验收 Word 无修复。
- 窗体三类不能走 `Fields.Add`（参数无效），要走 `FormFields.Add`。写出 `fldChar begin` 内 `w:ffData`（`name` / `enabled` / `calcOnExit` + `textInput` 或 `checkBox` 或 `ddList`），并常套书签。
- 手写最小 `ffData`（名 `Text1`，不写书签）打进 `insertField` 产物后，Word 打开无 Repair，`FormFields.Count=1`，另存去掉 `dirty`、保留 `ffData`、仍不补书签。因此库写 `ffData`、不写书签即可。
- 无 `ffData` 的 ` FORMTEXT ` 仍是域（`Fields.Count=1`），但不是窗体控件。

## 契约（已锁）

- 现有 `kind`（`simple` / `complex`）、`instr`、`code`（指令第一个词）保留。有 `ffData` 时名单再跟 `form`。
- `form` 字段顺序：`type`（`text` / `checkBox` / `dropDown`）、`name`、`enabled`；复选再跟 `checked`；下拉再跟 `items`。
- `insertField` / create `fields[]`：`instr` 与 `code` 恰好一个。只有 `instr` 时行为与 15 相同（不写 `ffData`）。
- `code`（大小写不敏感）：`PAGE` / `NUMPAGES` / `DATE` / `TIME` / `FILENAME` / `AUTHOR` / `LISTNUM` / `DOCPROPERTY` / `MERGEFIELD` / `STYLEREF` / `REF` / `FORMTEXT` / `FORMCHECKBOX` / `FORMDROPDOWN`。其余报 `InvalidField`。INCLUDETEXT / INCLUDEPICTURE / ASK / FILLIN 明示拒绝。
- `arg`：`MERGEFIELD` / `STYLEREF` / `REF` / `DOCPROPERTY` 必填非空；`LISTNUM` 可选（原样接到指令后）。其他 `code` 给了 `arg` 报未知字段或 `InvalidField`。
- 窗体 `code`：写 `ffData`。`name` 可选，缺省 `Text1` / `Check1` / `Drop1`。`checked` 仅复选。`items` 仅下拉。不写书签。
- `setField` 仍只改 `instr`，不改 `ffData`。
- 仍不求值，begin 仍标 `w:dirty`。仍写 `separate`。框内 / 注内 / 批注内仍不编。

## 不做

- 域引擎、打开时更新域、邮件合并执行
- pptx `a:fld`（契约不变）
- INCLUDETEXT / INCLUDEPICTURE 取外部文件
- EQ 公式排版（公式走 OMML）
- 为窗体域自动建书签
