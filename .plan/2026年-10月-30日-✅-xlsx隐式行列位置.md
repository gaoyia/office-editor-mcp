# xlsx 隐式行列位置

状态：✅ 已完成。
日期：2026-10-30

不在三种格式的待做表里，不占待做序号。来源是 2026-10-30 第二轮代码审计。领域 JSON 不变。

和「setCell 按表建一次索引」改的是相邻函数，两份不要同时做。本切片先把位置递推收成 `a1::row_after` / `a1::place_cell`。

## 现象

ECMA-376 §18.3.1.73、§18.3.1.4：`<row>` / `<c>` 可以不写 `r`，位置按前一个兄弟递推。

对照代码之后，原计划里的两处并不一样：

- inspect 和公式索引跳过没有 `r` 的格子。手写三行、每行三格都不写 `r`，改之前 inspect `A1:C3` 是 0 格。这是要修的。
- `setCell` 在改表之前已经调用 `make_refs_explicit`，把省略的 `r` 写成显式编号，再按编号找行和格子。写 B2 不会插出第二格，写 A5 也不会把行序打乱。原计划说的「不给已有格子补 `r`」和「修插入位置」不做。

## 不做

- 不改 `find_row_insert_pos` / `find_cell_insert_pos`。它们仍把没有 `r` 的行当成 0。`setCell` 进来之前已经写成显式 `r`。
- 不改「setCell 按表建一次索引」。

### 1. 复现

手写三行，每行三个格子，行和格子都不写 `r`。改之前 inspect `A1:C3` 读到 0 格。`setCell` 写 B2、A5 时，B2 只有一格，A5 排在第 3 行后面。

### 2. 文档

`docs/json-contract-xlsx.md`：

- 没有 `r` 或 `r` 解析不了时，行号是上一行加一（第一行是 1），格子列号是同一行上一格加一（第一格是 A），行号用所在行。合法的格子 `r` 以它自己为准。
- `setCell` 改表之前把省略的 `r` 写成显式编号。已经合法的不改写。

### 3. 实现

`a1::row_after` 与 `a1::place_cell` 是唯一的递推。inspect、公式索引的 `for_each_cell`，以及 `make_refs_explicit` 都走它们。解析不了的 `r` 与省略同等对待：读的时候按递推位置出现，写的时候补上显式 `r`。

### 4. 验收

- 上述样本 inspect 读到 9 格，A1 到 C3 的值是 1 到 9。
- `setCell` 写 B2 改的是原格，写 A5 新行在第 3 行之后。
- 样本是手写的，不是 create 的原样产物。create 会写 `r`，手测里先去掉再交给 apply。
- `cargo test -p ooxp --lib --tests` 全过。
- `cargo fmt --all` 与 `cargo clippy --all-targets --all-features -- -D warnings` 通过。
- 手测：Excel 16.0 打开 `setCell` 的产物，不报修复，A1 为 1，B2 为 50，A5 为 70。
