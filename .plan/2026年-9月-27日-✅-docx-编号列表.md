# docx 编号列表

状态：✅  
日期：2026-09-27

从 `roadmap/docx.md` 拆出待做序号 0。段落可能带 `w:numPr`，inspect 只当普通段。不能改编号定义。

## 目标

inspect 能看见段落的编号实例与级别。apply 能套用、去掉编号，能改 `numbering.xml` 里被点名的抽象定义（格式、起始值）。不算「这一段屏幕上显示几」。

## 已锁定

- 不实现编号计算引擎。树上不出现「显示为 3.」这类结果。
- 脚注编号已有 `setNoteNumbering`，节行号已有 `setLineNumbering`，不要混进本文。
- 编号定义在 `/word/numbering.xml`（关系 `/numbering`）。文档根始终 `numberingCount`（`w:num` 且 `numId` 不为 0 的个数）。页眉页脚容器不挂这份计数（整篇共用一份定义）。
- 编号实例 id 用 XML 的 `w:num/@w:numId`：`num:{numId}`。抽象定义 id 用 `w:abstractNum/@w:abstractNumId`：`abstractNum:{abstractNumId}`。`numId` 为 0 表示无编号，不进树。
- `scope.numbering` 为 true 时根上列出 `numberings`（按 `w:num` 文档顺序）。每条带该实例指向的抽象定义级别；`w:lvlOverride` 盖在对应 `ilvl` 上。xlsx / pptx 的 `scope.numbering` 报 `InvalidField`。
- 段落只读自己的 `w:pPr/w:numPr`，不解析 `styles.xml` 继承。有 `numPr` 且 `numId` 非 0 时段落出现 `num`、`ilvl`（缺 `ilvl` 当作 0）。框内 / 注内 / 批注内的段若自带 `numPr` 仍能看见，但编号 op 只接受正文或页眉页脚段落。
- apply：`insertNumbering`（`id` 为 `docx:document`，`kind` 为 `decimal` 或 `bullet`）写入一份抽象定义加一个实例。`setNumbering` 的 `id` 为 `abstractNum:{n}`，改该级 `numFmt` / `start` / `lvlText`。`setParaNumbering` 的 `id` 为段落 id，`num` 为 `num:{n}` 或 `null`（去掉 `numPr`）。
- create 本期不写编号。pptx / xlsx 上对应 op 报 `InvalidField`。

## 不做

- 自动列表样式推断
- 与 Word 像素级一致的悬挂缩进计算（缩进值可以写 XML，不算排版）
- 样式继承的编号（跟样式切片）

## 前置

无。

## 验收

另存带多级列表能读到级别；改成圆点或去掉编号后 Word 无修复。
