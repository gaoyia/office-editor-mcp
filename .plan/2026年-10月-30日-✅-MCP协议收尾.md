# MCP 协议收尾

状态：✅ 已完成。
日期：2026-10-30

不在三种格式的待做表里。`mcp` 模式只在 `.plan/` 记账。领域 JSON 不变。

## 现象

2026-10-30 审计时读 `crates/ooxp-cli/src/mcp.rs` 并实测，有三处和协议或文档对不上：

- **不以 `{` 开头的行被静默丢掉。** `read_message` 跳过既不以 `{` 开头、也不是 `Content-Length:` 的行。实测发一行乱码，收不到任何回复。`docs/cli.md` 写的是「JSON-RPC 解析失败仍是 `-32700`」。
- **批量请求被静默丢掉。** 以 `[` 开头的 JSON-RPC 批量请求走的也是上面那条路，不回任何东西。
- **`initialize` 原样回显客户端的 `protocolVersion`。** 客户端发什么版本，就回什么版本，等于声称支持所有版本，包括本程序没实现的行为（比如某些版本要求的批量请求）。

## 不做

- 不改六个工具的参数，不改领域 JSON。
- 不新增 MCP 能力（资源、提示词等）。

### 1. 文档

`docs/cli.md` 已写明：

- 一行一条时，空行跳过。`Content-Length` 头仍按帧读。其余非空行都当作一条消息。不是 JSON 就回 `-32700`，`id` 为 `null`。
- 批量请求不支持，回 `-32600`，`id` 为 `null`。
- 支持的协议版本是 `2024-11-05`、`2025-06-18`、`2025-11-25`。请求的版本在名单里就回它，否则回 `2025-11-25`。
- 不认 `2025-03-26`：那一版要求必须收下批量请求。
- 不认 `2026-07-28`：那一版取消了 `initialize`。

### 2–4. 实现

- `read_message` 不再跳过非空的非帧头行，交给 `reply_with_lang`。
- JSON 数组回 `-32600`。
- `initialize` 按支持名单协商版本。

### 5. 验收

- 乱码行回 `-32700`。批量请求回 `-32600`。`--lang en` 时这两条 `message` 是英文。
- 名单内的版本原样回。`2025-03-26`、`2026-07-28`、空串和缺字段回 `2025-11-25`。
- `cargo test --workspace` 全过。
- `cargo fmt --all` 与 `cargo clippy --all-targets --all-features -- -D warnings` 通过。
- 不改写出的 Office 内容，没有跑 Office。
