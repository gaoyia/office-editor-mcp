# apply 开始前固定 id

状态：✅ 已完成。审计点名的遗漏已接到同一个查找入口。
日期：2026-10-30

不在三种格式的待做表里，不占待做序号。这是缺陷修复，记录见 `.bugfix-reports/2026年-10月-30日-✅-按位置编号的id在同一次apply里漂移.md`。

排在 2026-10-30 审计拆出的重构计划前面。

用户 2026-10-30 决定：apply 开始前，把所有 op 里的 id 按原文件解析成节点；后面的 op 不受前面增删的影响。

## 目标

一次 apply 里，每条 op 点名的对象，都是调用方 inspect 原文件时看到的那个对象。

- 被前面 op 删掉的对象，后面再点名时报 `IdNotFound`。
- 同一批里新建的对象，要等下一次 inspect 拿到 id 才能点名。

本份是第一期，只做已经实测出问题的两类：

- docx 段落类 id：`para:index:{n}`，以及页眉页脚、框内、注内、批注内的 `…/para:index:{k}`
- pptx `slide:{n}`，以及挂在它下面的所有 id

## 不做

- 不改 id 的字符串格式。
- 不改有内容编号的 id（`para:{paraId}`、`pic:{cNvPrId}`、`shape:{shapeId}` 等）。它们本来就不漂移。
- 第二期的其余位置 id 不在本份做，见文末。

### 1. 文档

- `docs/json-contract.md` 的「稳定 id」一节加一条：一次 apply 里，所有 id 都按 apply 开始时的文件解释。
  - 被前面 op 删掉的对象，后面再点名报 `IdNotFound`。
  - 同一批里新建的对象不能按位置点名。
- `docs/json-contract-docx.md` 第 18–19 行：「只够同一次 inspect 之后立刻 apply」改成指向上面这条。
- `docs/json-contract-pptx.md` 第 228 行：「按新顺序计」改成上面这条。
- 契约里所有写着 `after` / `start` 一类、引用别的对象的字段，同样按这条解释，在文档里点明。

### 2. 做法

2026-10-30 定下的做法：

- pptx：apply 开始时记下每页的 `p:sldId/@id`。增删移动之后重新列出页，但 `index` 改回开始时的页号。查找按这个页号，不按当时的位置。新页的页号记 0，不能被旧的 `slide:{n}` 点中。
- docx：部件第一次载入时，按 `find_p` 的同一套顺序给已有 `w:p` 写内存属性 `ooxp:pin`。文本框、注、批注各自从 1 起。写出时丢掉这个属性。本批新建的段落写成空 pin，不占用旧序号。
- create 用的是 `para:{paraId}` 和直接拼包，不在同一批里按位置点名新对象。产物不变。

约束有三条：

- 产物里不能留下任何痕迹。
- 不能因为前置解析把本来不改的部件标脏。
- 删掉的对象后面再点名时要能识别出来，报 `IdNotFound`。

候选做法：

- pptx：apply 开始时把 `slide:{n}` 换成该页的 `p:sldId/@id`，之后一律按 `sldId` 找页。这是文件里本来就有的稳定编号，不需要临时标记。
- docx：apply 开始时找到被点名的 `w:p`，给它挂一个本库专用的临时标记；之后按标记找，写回前统一摘掉。或者找到更简单、同样满足上面三条约束的做法。

还要核对 create 的内部调用：

- docx 和 pptx 的 create 都复用 apply 的 op。逐个核对它们是否在同一批里先插入、再按位置点名新对象。
- 有的话，改成分批调用，或者改用内容编号的 id，保证 create 的产物不变。

### 3–4. 实现

- 各格式 apply 入口在执行第一条 op 前做一遍前置解析。执行阶段只认解析结果。
- 解析失败（原文件里就没有这个对象）照旧报 `IdNotFound`，报错时机提前到执行第一条 op 之前。

### 5. 验收

- pptx：先删 `slide:1`，再改 `slide:3` 上的形状，改到的是原来的第 3 页。
- pptx：`moveSlide` 之后再点名被移动的页，指向的仍是同一页。
- 现有 docx、pptx 测试全过。依赖「按新顺序计」的测试改了期望：

## 审计发现的遗漏（2026-10-30）

固定的做法本身是对的：docx 用 `ooxp:pin` 标段落，pptx 用 `SlideFreeze` 冻结页名单。问题是只有一部分 op 接上了，其余 op 仍按当前顺序找对象。页数或段数多时，它们会静默改到别的对象上。契约（`docs/json-contract.md`「稳定 id」）已经承诺全部 op 都按 apply 开始时解释。

实测（先删或先插，再点名原来的对象）：

- docx：在 P1 后插一段，再对 `para:index:4`（原来的 P4）发下面的 op。
  - 对的：`setParaText`、`insertHyperlink`、`setParaFormat`、`insertFootnote`
  - 落到 P3 上的：`insertBookmark`、`insertPara`、`insertSection`
  - `deletePara` 删掉的是 P3，P4 还在
- pptx：4 页，删掉 `slide:1`，再对 `slide:3`（原来的 S3）发 op。
  - 对的：`setShapeText`、`setTransition`、`setSlideHidden`、`setNotesText`、`moveSlide`、`insertSlide`、`setSlideLayout`、`insertComment`、`insertShape`、`setShapePos`、`deleteShape`、`setShapeFormat`
  - `insertTable` 落到原来的 S4 上
  - `insertHyperlink` 写进了删页后排在第 2 位的那一页，不是原来的 S2
  - `insertField`、`insertConnector`、`insertMath` 也按当前顺序找页

代码上的原因：

- docx：`para.rs` 第 1416、1690、2351、2604 行与 `smartart.rs` 第 1232 行仍用 `idx == *n` 比当前位置，没有走 `index_matches`。还要查有没有别的模块自己数段落。
- pptx：只有 `apply.rs` 入口里直接取页的 10 处和 `slides.rs` 改用了 `frozen.get`。各对象模块里自己找页的地方没有接上。

补做（2026-10-30）：

- 段落是否对上 `para:index` 只走 `same_para`。它认 `ooxp:pin`，新建段落的空 pin 不占用旧序号。`find_paragraph_path`、`insert_p_after`、`remove_p_at`、`is_last_collected` 和 SmartArt 的段落匹配都改走它。
- 页号只走 `SlideFreeze::slide_at_start`。`index` 在增删重排之后由 `restore_indexes` 改回开始时的页号，新页是 0。`resolve_tree_part` 和 `ensure_host_part` 都用它，不再按当时的位置取 `slides[n - 1]`。
- 回归：docx 先在 P1 后插段，再对原来的 P4 做 `deletePara`、`insertPara`、`insertBookmark`、`insertSection`。pptx 先删第 1 页，再对原来的第 3 页做 `insertTable`、`insertConnector`、`insertMath`、`insertField`、`insertHyperlink`。都落在原来的对象上。
- 第二期的其他位置编号仍不在本份。

第二次审计又补的（2026-10-30）：

上面的补做之后，pptx 仍有 5 处只认 `sldIdLst` 当前顺序，删页或移页之后会静默落到别的页上，已在审计里补上并加了回归测试：

- `insertSlide` 的节归属：邻页编号改用 `SlideMeta.sld_id`，不再按 `index` 回头查 `sldIdLst`。删掉不再使用的 `slide_st_id`。
- `insertZoom` 的目标页：`zoom.rs` 的 `slide_meta` 改走 `slide_at_start`。
- `insertCustomShow` / `setCustomShow` 的 `slides`、`setSlideSection` 的页、`insertSlideSection` 的 `start`：这几个函数只认当前顺序，`apply.rs` 调用前用 `slide_now` 把开始时的页号换成当前位置。
- 回归测试：`pptx_slides.rs` 的 `delete_then_slide_refs_keep_original_slide` 与 `delete_then_section_ops_keep_original_slide`。改动前两条都失败，改动后通过。

两轮审计用「先增删、再点名原对象」扫过的 op：

- docx 26 种：`setParaText`、`insertField`、`insertBookmark`、`insertHyperlink`、`insertFootnote`、`insertEndnote`、`insertPicture`、`insertTextBox`、`insertShape`、`insertConnector`、`insertContentControl`、`insertRuby`、`insertCaption`、`insertIndexEntry`、`insertMath`、`insertEditRange`、`insertTable`、`insertToc`、`setParaStyle`、`setParaFormat`、`insertComment`、`insertChart`、`insertSmartArt`、`insertPara`、`deletePara`、`insertSection`。全部落在原来的段落上。
- pptx：除上面列出的，还有 `insertPicture`、`insertChart`、`insertSmartArt`、`insertModel3d`、`insertAnim`、超链接跳转目标。全部落在原来的页上。
- 没有扫到的 op 仍走同两个入口（`same_para`、`slide_at_start` / `frozen.get`），但没有逐条实测。

找页收成一套（2026-10-30）：

- 原来 pptx 有两套等价的找页方法：`frozen.get` / `frozen.pos` 按 `sld_id` 找，`slide_at_start` 按被 `restore_indexes` 改写过的 `index` 找。`index` 因此在增删页前后含义不同，插页的节归属就是这样错的。
- 现在 `SlideMeta` 多一个 `start`：apply 开始时的页号，本批新建的页为 `None`。`index` 只表示当前位置，不再改写。
- 按开始时页号找页只走 `shape::slide_at_start` 与 `shape::pos_at_start`，都按 `start` 匹配。`SlideFreeze` 只在增删重排后用 `mark_start` 把 `start` 标回去。
- `slides.rs` 各函数与 `apply.rs` 的 `slide_now` 不再接收 `frozen`。超链接跳转目标改按 `start` 匹配。
