# 限制故事与共享图模块（脑暴备忘）

状态：💤 只写备忘，不实施、不改契约、不改代码  
日期：2026-09-28

xlsx / docx / pptx 第一期顺序待做都已空。下面两件事是用户后补，不进三种格式的全量待做表。

## 1. 限制故事里的图形对象

Word 打开后可能报：「无法将图形对象置于文本框、标注、批注、脚注或尾注中」。希望发请求时就拦住，不要等 Office 修包或弹窗。

### 现状

错误身份已经有：`ErrorKind::GraphicInRestrictedStory`，码是 `InvalidField`。中文文案与 Word 那句同义。

现在真正用到它的只有 `insertTextBox`：宿主段落是脚注、尾注或批注时，在 `crates/ooxp/src/docx/apply.rs` 的 `apply_insert_txbx` 里直接拒绝。正文和页眉页脚仍可插框。

同一文件里，`insertPicture` / `insertChart` / `insertSmartArt` 仍接受注内、批注内、框内段落 id。这与 `docs/json-contract-docx.md` 一致：inspect 会列出这些故事里的图 / 图表 / SmartArt，apply 也可以往里插。OLE 本期本来就不编框内、注内、批注内。

因此：库已经能写出 Word 事后才抱怨的包。校验发生在 apply，不是 JSON 解析阶段。

### Word 这条限制实际指什么

这是 Word 故事（story）边界，不是「任何容器都不能放图」。

| 宿主 | 是否像 Word 说的那种限制故事 | 备注 |
| --- | --- | --- |
| 正文、页眉、页脚段落 | 否 | 插图、图表、SmartArt、文本框都是正路 |
| `w:txbxContent`（文本框 / 标注） | 是 | 往框内再塞 `w:drawing` 图形，正是那句「置于文本框、标注」 |
| 脚注 / 尾注 | 是 | 独立部件，但是限制故事 |
| 批注 `w:comment` | 是 | 独立部件 |
| 表格单元格 | 否 | 单元格段落跟正文同一套规则 |

「标注」在 DrawingML 里通常还是带 `w:txbxContent` 的形状，不必另开一种 id。

要不要在解析 `ops` 时就拒，而不是进到 apply 才拒：效果相同，都是不写文件。更值得先做的是把「哪些 op × 哪些宿主」一次列清，并用 Word 16.0 亲手插一次对照，不要只凭那句报错猜。

建议对照（未做）：

1. Word 能否往脚注 / 批注 / 文本框里插普通图、图表、SmartArt、文本框。
2. 库 `insertPicture` 进这三处之后，Word 是直接修包、打开后那句错误、还是其实能显示。
3. 已有文件里若本来就有注内图（别人或旧版写的），inspect 是否继续列出；apply 改已有对象与「新插」是否要分开。

未对照之前，不要把契约改成一律拒绝。现在契约写着可以插，清单也按这个验收过。若对照证明 Word 16.0 一律打回，再改 `docs/json-contract-docx.md`，把 `insertPicture` / `insertChart` / `insertSmartArt` / `insertTextBox` 在限制故事上的行为改成 `InvalidField`（复用 `GraphicInRestrictedStory`），并补手测。已存在的对象仍应能 inspect、导出、按需删除。

### xlsx / pptx 不要照搬

xlsx 没有脚注、尾注，也没有 Word 那种 `w:comment` 故事。工作表批注是线程化注释，画在格子上，不是一段可往里塞 `w:drawing` 的故事。工作表文本框是 `xdr:sp`，里面再放图是另一套 DrawingML，不能套 `GraphicInRestrictedStory` 那句 Word 原文。

pptx 的演讲者备注是完整的 `notesSlide`，上面本来就可以有图、图表、SmartArt（序号 9 已过）。现代批注内图只能 `exportMedia`，不能 `insertPicture`。这两条都不是 Word 的限制故事。不要对 pptx 备注或批注去报 `GraphicInRestrictedStory`。

结论：先只在 docx 上用 Word 16.0 对照；xlsx / pptx 没有同构故事，默认不扩这条错误。

## 2. 图表与同类模块要不要再抽一层

### 已经共享的

`c:chart`（ECMA-376 §21.2）在 `crates/ooxp/src/chart/`：读类型与系列、改 cache、embedding、趋势线、误差线、次轴。三种格式的 apply 都调这里。

SmartArt 四件套在 `crates/ooxp/src/smartart/`：data 部件上的点、写四件套、清缓存。三种格式的宿主模块只负责 graphicFrame 外壳。

这与 AGENTS.md「`c:chart` 用 `crates/ooxp/src/chart/`」一致，不是新方向。

### 仍然分三套的

宿主外壳不能合并，id 和脏部件也不同：

| | docx | xlsx | pptx |
| --- | --- | --- | --- |
| 宿主 | `w:drawing` + 绕排 / 锚点 | `xdr:graphicFrame` + `twoCell` / `oneCell` | `p:graphicFrame` + `a:xfrm` |
| 图表宿主模块大约行数 | `docx/charts.rs` 3909 | `xlsx/chart.rs` 1842 | `pptx/chart.rs` 1291 |
| 共享 `c:chart` 大约行数 | `chart/mod.rs` 2110 + `remain.rs` 1602 + `embed.rs` 185 | 同左 | 同左 |
| SmartArt 宿主大约行数 | `docx/smartart.rs` 1789 | `xlsx/smartart.rs` 756 | `pptx/smartart.rs` 1069 |

请求解析也必须分家：docx 用段落 id，xlsx 用 `sheet:…`，pptx 用 `slide:N` 或 `slide:N/notes`。领域 JSON 不允许为了共享实现去改字段名。

### 建议（仍不实施）

1. 保持现在这层：共享「部件里的 `c:chart` / diagram data」，不共享「插进哪一种 drawing」。再往上抽一个跨格式 `insertChart` 会把三种锚点和三种 id 搅在一起，得不偿失。
2. 若以后觉得宿主模块太长，优先把「找 graphicFrame、写关系、写 Content Type」里确实逐字相同的小函数再下沉，不要先合并 `request.rs`。
3. 图（`pic:pic`）不要跟图表合成一个共享 crate。锚点、绕排、媒体关系三种格式差得更远。
4. 视频 / 音频只在 pptx 上有第一期实现，没有跨格式可抽。
5. 批注也已经分三套（docx `w:comment`、xlsx 线程化、pptx `p188`），不要为了「都叫批注」再做共享故事层。

## 不做

- 现在不改 `docs/` 契约，不改 apply 拒绝范围。
- 不把这两条写进 `roadmap/` 待做。三种格式顺序待做保持为空。
- 不把 Word 那句错误套到 xlsx / pptx。
