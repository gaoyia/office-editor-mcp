# xlsx 页眉页脚

状态：✅ 库测试与 Excel 16.0 手测 Xh1–Xh5 已过
日期：2026-09-27

从 `.plan/2026年-9月-27日-❌-xlsx-后续路线.md` 拆出序号 1。Excel 的页眉页脚不是 Word 那种独立 header 部件，而是工作表上的 `headerFooter`（ECMA-376 §18.3.1.46）加可选 `drawingHF`。本期做文本的查与改，以及页眉页脚里的图。不做 VML `legacyDrawingHF`。

规范线索：`oddHeader` / `evenHeader` / `firstHeader` / 对应 Footer（§18.3.1.45）。奇偶不同看 `differentOddEven`，首页不同看 `differentFirst`。图走 `drawingHF` 关系，不是工作表上的工作表 drawing。

契约真源：`docs/json-contract.md`、`docs/json-schema/request.schema.json`、`docs/errors.md`、`docs/architecture.md`、`docs/opc.md`、`docs/checklist-xlsx.md`。

## 目标

## 已锁定（写入契约后不要改）

- 这是工作表属性，不是文档级 header 部件。不要套用 `header:default:1/para:…`。
- 容器 id：`sheet:{name}/hf:{kind}:{side}`。`kind` 为 `odd` / `even` / `first`，`side` 为 `header` / `footer`。`{name}` 规则与现有工作表 id 相同。
- 文本就是该元素的可见字，不做 `&P` / `&D` / `&A` 这类代码的独立节点。inspect 报原文；apply 整段替换原文。
- 现行契约里 xlsx 的 `scope.headerFooter` 报 `InvalidField`。本期改成：为 `true` 时展开上述六个槽位的文本（没有的槽位仍列出，文本为 `null`）。省略或 `false` 则只有「有没有页眉页脚」的摘要，不倒出原文。
- 页眉页脚图 id：`{容器 id}/pic:{cNvPrId}`。只认 `drawingHF` 里锚点的直接子元素 `xdr:pic`。工作表 drawing 上的图仍走 `sheet:{name}/pic:…`，两套名单不混。
- `insertPicture` 的 `id` 必须是页眉容器 id 才能往该侧插图。对工作表 id 发 `insertPicture` 仍只插工作表图，不进页眉。
- 编辑 `legacyDrawingHF` / VML 报 `NotImplemented` 或不进树（开文档时写死一种，不要两种并存）。
- 对 `chartsheet` / `dialogsheet` 的页眉页脚本期只读文本，不插图。
- `create` 本期不写页眉页脚。docx / pptx 的页眉契约不动。
- 往页眉插图时新 `cNvPr/@id` 至少为 2。Excel 16.0 若 `drawingHF` 属性指向 id 1，会拒绝打开。

## 不做

- 编辑 VML `legacyDrawingHF`
- 页眉页脚里的图表、形状、OLE

## 验收

手测编号另开 Xh 组，写入 `docs/checklist-xlsx.md`。源文件必须是 Excel 亲手另存，至少有页眉文字；有图则再测换图。不要用库 `create` 产物当唯一样例。

- 无 `headerFooter` 时能看见有没有页眉；给了范围才有原文。
- 改奇数页页眉文字后 Excel 无修复，页眉里是新字。
- 有 `drawingHF` 图时 id 带 `hf:` 前缀；换图后无修复。
- 工作表图名单不含页眉图。
