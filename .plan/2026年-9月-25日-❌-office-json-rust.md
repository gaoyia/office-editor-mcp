# Office JSON Rust 工具（中低难度）

状态：❌ 未开始  
日期：2026-09-25

## 目标

用 Rust 做一套 **库 + 命令行**：入参为 JSON，对 `.docx` / `.xlsx` / `.pptx` 做 **创建** 与 **局部修改**。不复刻 Word 排版引擎，不实现 Excel 计算引擎，不做 PPT 完整动画时间轴。

「全量」指：在本阶段范围内，创建与修改都走同一套 JSON 契约，并做到 Office 能打开、常见样式在局部改字时尽量保留。不是覆盖 Office 全部功能。

## 范围

### 做（中低）

| 2 | OPC（ZIP + Content_Types + rels）打开 / 保存，未改部件原样写回 | ❌ |

| 4.2 | docx：从 JSON 创建简易文档（段落、标题） | ❌ |

#### 1 文档先行 ❌

1.1 写 `docs`：模块（opc / xlsx / docx / pptx / json / cli）、inspect 树与 apply 补丁的数据流、错误类型。❌  
1.2 写领域 JSON 契约 `schemaVersion: 1`：`action` 为 `inspect` | `create` | `apply`。❌  
1.3 规定 inspect 树的稳定 id：xlsx 用工作表名 + A1；docx 用段落 id；pptx 用 slide + shape。❌  
1.4 规定 apply 禁止交回整棵树；create 才允许从 JSON 生成新包。❌  
1.5 用户确认 1.1–1.4 后再开工 2 及以后。❌  

#### 2 OPC 公共层 ❌

2.1 打开 `.docx` / `.xlsx` / `.pptx` 作为 ZIP，列出部件路径。❌  
2.2 读写 `[Content_Types].xml` 与 `_rels/.rels`、部件级 `.rels`。❌  
2.3 按路径读取部件字节；修改后写回指定部件。❌  
2.4 保存时未改动的部件保持原字节，不重排、不美化无关 XML。❌  
2.5 验收：打开样例再原样保存，Excel/Word/PPT 能打开。❌  

#### 3.1 xlsx 读取与局部修改 ❌

3.1.1 `inspect`：列出工作表；按区域（如 `A1:D20`）返回地址、显示值、公式字符串。默认不吐整本。❌  
3.1.2 `apply`：`setCell` 写入数字、文本、布尔或空。❌  
3.1.3 `apply`：`setCell` 写入公式字符串（如 `=SUM(A1:A10)`），不在库内求值。❌  
3.1.4 改公式或依赖单元格后，清除过期缓存值或标打开后需重算。❌  
3.1.5 只改目标单元格 XML，其余工作表与样式部件原样保留。❌  
3.1.6 验收：改若干格后 Office 能打开，未改区域观感基本不变。❌  

#### 3.2 xlsx 创建 ❌

3.2.1 从 JSON 生成含至少一个工作表的空白/简易工作簿。❌  
3.2.2 JSON 可声明单元格值与公式文本。❌  
3.2.3 产出文件 Excel / WPS 能打开。❌  

#### 4.1 docx 读取与局部修改 ❌

4.1.1 `inspect`：返回大纲（标题）与段落列表，每段带稳定 id 与可见文本。可按范围截断。❌  
4.1.2 `apply`：按段落 id 替换文本，尽量保留该段现有 run / 样式，不整篇重建 `document.xml`。❌  
4.1.3 不在本项做修订痕迹、页眉页脚精细编辑、复杂表格结构编辑（见暂缓）。❌  
4.1.4 验收：改一段落后标题样式与未改段落仍在；Word 能打开。❌  

#### 4.2 docx 创建 ❌

4.2.1 从 JSON 生成简易文档：正文段落与标题样式。❌  
4.2.2 产出文件 Word 能打开。❌  

#### 5.1 pptx 读取与局部修改 ❌

5.1.1 `inspect`：按页列出形状 id 与文本框可见文字。❌  
5.1.2 `apply`：按 slide + shape 改字；不删除重建形状（避免 id 变化绑空动画）。❌  
5.1.3 不修改 `<p:timing>`（动画完整写入见暂缓）。❌  
5.1.4 验收：改一页文字后其余页不变；PowerPoint 能打开。❌  

#### 5.2 pptx 创建 ❌

5.2.1 从 JSON 生成简易演示文稿：若干页、文本框。❌  
5.2.2 产出文件 PowerPoint 能打开。❌  

#### 6 CLI ❌

6.1 从文件路径或 stdin 读入领域 JSON。❌  
6.2 按 `action` 分发 inspect / create / apply。❌  
6.3 inspect 将 JSON 树打到 stdout；create / apply 写出目标文件路径。❌  
6.4 本表不包含 MCP；MCP 用同一套领域 JSON，另开任务用 JSON-RPC 2.0 封装。❌  

**建议顺序：** 1 → 2 → 3.1 → 3.2 → 6（xlsx 路线跑通）→ 4.1 → 4.2 → 5.1 → 5.2。

### 暂缓 💤

- PPT 通用动画时间轴（可读列表可二期；完整写入不做）
- Word 修订痕迹、页眉页脚精细编辑、复杂表格结构编辑
- Excel 公式求值、数据透视、图表渲染
- `.doc` / `.xls` / `.ppt` 二进制
- 分页与 Word 像素级一致

## 架构要点

- 自研 OPC + 定点改 XML，不要拼三套互不兼容的高层 crate 当唯一模型。
- **不依赖** `office_oxide`。需要对照时查阅其公开仓库即可，不要在本仓库添加三方包目录或 git 子模块，也不要写入 Cargo 依赖。
- 修改策略：**手术刀**。只改目标节点，未知命名空间与未触及部件原样保留（Transitional OOXML，对齐 Office 默认文件，不是项目「旧版兼容」）。
- **两层 JSON，不要混成一种：**
  - 领域契约：`inspect` / `create` / `apply` 的文档操作 JSON（库与 CLI 的入参）。
  - 传输：MCP 使用 JSON-RPC 2.0（stdio）。RPC 的 `params` 里放领域 JSON，不要用 JSON-RPC 信封当单元格/段落模型。
- **已确认的交互：** 模型阅读 `inspect` 得到的精简 JSON 树（带稳定 id），再发 `apply` 操作列表改文件。对模型而言是「看树改文档」；真源始终是 OPC/XML。禁止把 inspect 树当完整 IR 改完后整包重生（`create` 新建除外）。
- 禁止用「整份文档 JSON 再生成」作为修改路径。
- 规范查阅用 `standards/md/`，不要整本打开 ECMA-376 五千页 PDF。

## 阶段出口

1. 空白 xlsx/docx/pptx 可从 JSON 创建，Office 能打开。
2. 对样例文件 apply 改一格 / 一段 / 一页文字后，Office 能打开，未改区域观感基本不变。
3. 公式只作为字符串写入；不在库内求值。
4. 单元测试覆盖 JSON 契约与 XML 不变量；有手工打开清单。
