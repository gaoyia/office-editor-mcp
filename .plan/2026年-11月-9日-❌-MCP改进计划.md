## 缘起

2026-11-9 用 `ooxp mcp`（v0.1.2，darwin-arm64 预编译包）生成一份 6 页 pptx，再用 `apply` 另存动画版。过程是 1 次 `create`、1 次 `apply`（474 个 op、150 个形状）、1 次 `apply`（36 个 op）。下列现象都在本机复现：

- `help` 的 `q=渐变` 与 `q=图层` 各返回 0 条；`q=背景` 只返回 docx 的 `setPageBackground`。
- `setShapeFill` 只接受 6 位十六进制色值，页面深色底只能用全页矩形充当，落日与沙丘靠 3 层椭圆叠出。
- `insertShape` 的 x 为 -1200000 时报 `InvalidField: x 从 0 起`，半出血形状做不了。
- `inspect` 的 `scope` 传 `shapes` 或 `textBoxes` 都报 `InvalidField: 不认识的字段`，实际只认 `slide` 加 `maxShapes`。
- 474 个 op 的 `apply` 在第 16 条失败时只报 `ops[16].x`，不带对象 `id`、名称或字段路径。
- `help` 摸清 pptx 的 create 契约要 8 次以上往返，一次只展开一层 `$ref`。
- 生成的 pptx 无法在工具内自检，只能用项目外的 macOS Quick Look 拆成单页再拼图检查。

`create`、`inspect`、`apply` 的领域 JSON 契约已经能支撑完整的读写闭环。下面要补的是调用方能不能一次写对、写错了能不能查、页面能不能做得更好看。

## 目标

让调用方一次写出带几何与颜色的页面，提交前能检查布局，失败时能定位到具体对象。范围分三块：调用方自检、pptx 表达力、安装与分发。

## 不做

下列条目与仓库已定约束冲突，本计划不纳入：

- 渲染、导出 PNG 或 PDF、生成缩略图。`docs/architecture.md` 与 `roadmap/pptx.md` 都写明不做渲染；改为只返回几何数据的 `layoutCheck`。
- 放映引擎、任意时间轴树、与 PowerPoint 像素级一致。`roadmap/pptx.md` 的永不做清单保持原样，`setTiming` 继续报 `UnsupportedOp`。
- 排版引擎、按新画布重排。`layoutCheck` 只做估算和提示，不改文件。
- 为 JSON-RPC 信封改领域 JSON 字段、把 `ops` 拆成 MCP 专用工具参数。`AGENTS.md` 禁止。
- 在 `roadmap/` 为命令行 MCP 开格式待做序号。

## 对架构的影响

阶段一只碰 `crates/ooxp/src/help.rs`、`crates/ooxp/src/dispatch.rs`、`crates/ooxp/src/error/` 和新增的只读动作，不动 `opc` 写回，也不改三个动作的语义。

`apply` 的事务性会碰到写回边界。动手前先读 `crates/ooxp/src/dispatch.rs` 与 `crates/ooxp/src/opc/` 的落盘路径，确认当前是逐 op 改内存树后一次写盘，还是每条都写；顶层设计确定后再动代码。

### 写回路径结论（2026-11-9 读码取证）

- `dispatch.rs:312-330` 调 `pptx::apply`；`pptx/apply.rs:37-49` 一次 `Package::open_bytes`，循环里逐条改内存树，`:639` 唯一一次 `save_to_vec`。
- `opc/package.rs:231-277` 的 `save_to_vec` 只返回 `Vec<u8>`，不碰磁盘。未脏部件复制原 zip 字节，脏部件重新 Deflate。
- `json.rs:281-316` 的 `write_atomic` 在同目录写 `.ooxp.tmp` 再 `fs::rename`，落盘是一次原子替换。
- 现已是全批原子：任一 op 出错由 `?` 提前返回，内存树丢弃、原文件不变，不需要新增回滚机制。
- 第 4 项只剩 `dryRun`：在 `save_to_vec` 之前短路返回，不写盘。要返回部件清单，还要给 `Package` 加只读的脏部件名访问器，不动写回逻辑。
- 代码里没有 `OpArchy`、`transaction`、`rollback` 这类机制，也没有 `dryRun` 字段，后续命名不要沿用前三个词。

阶段二只在 `crates/ooxp/src/pptx/` 内扩展写入，不新增跨格式引用，不新增 crate，不往 `Cargo.toml` 加三方依赖。稳定 id 规则不变：新 `cNvPr/@id` 仍取该宿主已有最大值加 1。

## 第 1 项复现证据

环境：本仓库 `b36aea0` 加 `7fded8a` 本地编译的 `ooxp` v0.1.2，darwin，CLI 从 stdin 读领域 JSON。被 inspect 的文件是工作区那份 6 页 pptx。

请求与返回：

- 请求 `{"action":"help","name":"inspectScope"}` 返回 `kind=def`，`fields.properties` 是三格式键的合并表，含 `shapes`、`textBoxes`、`textBoxContent` 等，没有格式标注。
- 请求 `{"action":"inspect","format":"pptx","scope":{"shapes":true}}` 返回 `InvalidField`，消息「不认识的字段：shapes」，`path` 为 `shapes`，退出码 2。
- `crates/ooxp/src/pptx/request/mod.rs:82-109` 的白名单只列 23 个键，不含 `shapes` 与 `textBoxes`。
- `help` 的 `fields` 取自 `docs/json-schema/request.schema.json` 的 `inspectScope`（`help.rs:566-596`），该定义按 action 分支、不按 format 分支。

根因有两层，都要处理：

- `help` 把别格式的键当成本格式可用，调用方照着写必然失败。这层要改 `help.rs`，契约已按下节拍板。
- 文档互相矛盾，`0074c3a` 已修四处：`docs/json-contract.md` 的 `scope.tables` 与 `scope.hyperlinks` 范围、`docs/json-contract-docx.md` 的 pptx 键清单。
- 另两处是 `docs/errors.md` 漏 `scope.inks`，以及 `docs/json-contract-pptx.md` 的「不给 slide 合法」名单漏 `media`、`model3ds`、`inks`、`maths`。现以 pptx 分册的 23 个键为唯一清单。

## 阶段一契约决定（2026-11-9 用户拍板）

四项已写进 `docs/`；拍板时 Rust 代码未动，现已按下述决定实施完成。第 2 项本次不拍板。

- 第 1 项：`name=inspectScope` 带 `format` 时只返回该格式认的键；不带 `format` 返回现有 `kind=chooseFormat`，不给 `fields`。
- 适用格式写在 `docs/json-schema/src/shared/envelope.json` 的 `inspectScope.properties.<key>.formats` 上，共 59 个键。`help.rs` 按它过滤，不在代码里另抄键表。
- 请求 schema 里的 `inspectScope` 仍是三格式并集，跨格式键继续由各格式 `parse_scope` 拒绝。
- 第 3 项：apply 失败时 `error.objectId` 放对象 id，`error.objectName` 放可选对象名。
  `path` 仍指向入参例如 `ops[16].x`，`message` 仍是按语言渲染的短句。两个字段在构造该条 op 的错误时读取，读不到就省略。
- 第 4 项：`dryRun` 是 apply 的可选布尔字段，在 `save_to_vec` 之前返回标脏的部件名，不写盘，不新增回滚类型。
  成功响应带 `dryRun`、`opsApplied`、`parts`，不带 `path`。
- 第 5 项：`layoutCheck` 作为第七个动作加入 `tools/list`，工具名就是动作名，参数仍是整份领域 JSON 或单独 `requestPath`。
  只读几何、不写文件、不生成图片、不调用 Office。本期只对 pptx 实现，返回包围盒、越界、重叠与文字溢出估算。
- 第 2 项：`$ref` 展开方式本次不拍板，标 💤，不写契约、不进实施。

`scope.tables` 按用户核对结果改写，依据是 pptx 分册第 317 行与 `master.rs`。
幻灯片上的表进每页 `tables`；备注表只在 `scope.notes` 同开时出现在 `notes` 上。
母版与版式上的表只在 `scope.masters` 同开时出现在该母版或版式上。

实施阶段已同步 `crates/ooxp-cli/src/mcp.rs` 的 INSTRUCTIONS：「六个动作」「六个工具」改为「七个」，英文说明同步；`tools/list` 同时加上 `layoutCheck`。

## 阶段

### 阶段一：调用方自检（不写 XML）

1. 修 `inspect` 的 `scope` 契约不一致。这属于 Bug，按工程原则先在 Debug 模式留下复现证据，包括请求 JSON、返回体和 `docs/json-contract-pptx.md` 对应段落，再决定是删掉 `inspectScope` 里 pptx 不认的字段，还是补实现。
2. `help` 增加一次展开 `$ref` 的能力，或在 `docs/json-schema/` 提供可下载的完整 schema。契约怎么选，先写进 `docs/cli.md`。
3. `apply` 的错误正文带 `ops` 下标、对象 `id`、对象名和字段路径。文案改 `crates/ooxp/src/error/messages/`，`docs/errors.md` 同步。
4. `apply` 的 `dryRun` 与事务性。`dryRun` 只返回会被改动的部件清单，不写盘；失败时全部回滚。
5. 新增只读动作 `layoutCheck`，返回每页形状的包围盒、越界、重叠和文字溢出估算。它不生成图片，不调用 Office。

### 阶段二：pptx 表达力（先探测，再挂序号）

6. 把 `setPageBackground` 扩到 pptx，写 `p:bg`。docx 版已支持纯色、渐变与图片填充，复用它的字段设计。
7. `setShapeFill` 支持 `alpha`、`gradFill` 与 `blipFill`，让形状能有透明度和渐变。
8. `insertShape`、`insertPicture` 支持 `index`、`before` 或 `after` 指定 `spTree` 插入位置；也可以改成独立的 `setZOrder`。create 阶段的 `pictures` 固定写在 `shapes` 之后，调用方目前只能倒推顺序。
9. `insertShape` 放开负坐标，允许形状出界。
10. `pptxShapeCreate` 合并 `insertShape` 的 `x`、`y`、`cx`、`cy`、`prst`、`fill`、`line`，让 create 一步写出带几何的页面。

第 6 到 10 项都要先按 `roadmap/pptx.md` 用 PowerPoint 16.0 另存探测，确认写出的 XML 能被 Office 打开且无 Repair，再挂待做序号。

### 阶段三：安装与分发
