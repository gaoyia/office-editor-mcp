# MCP 改进计划：设计表达力与调用方自检

状态：❌ 未开始。本计划列 13 项改进，分三个阶段；本阶段只写这份计划，不改 `docs/`、不改代码、不跑测试。
日期：2026-11-9

这份计划不占 `roadmap/docx.md`、`roadmap/xlsx.md`、`roadmap/pptx.md` 的待做序号。处理方式与 `.plan/2026年-10月-29日-✅-命令行MCP.md` 相同：用户点名的改进提案，命令行与跨格式部分在 `.plan/` 单记一份。

涉及 pptx XML 写入的条目要另按 `roadmap/pptx.md` 的「先探测再进待做」办理。先用 PowerPoint 16.0 另存探测，再挂新序号。第七轮待做当前已做完，未探测的条目不算欠账。

契约真源仍是 `docs/`。下面每一条在动代码之前，先各自更新对应的 `docs/` 并等用户确认。

## 缘起

2026-11-9 用 `ooxp mcp`（v0.1.2，darwin-arm64 预编译包）生成一份 6 页 pptx，再用 `apply` 另存动画版。过程是 1 次 `create`、1 次 `apply`（474 个 op、150 个形状）、1 次 `apply`（36 个 op）。下列现象都在本机复现：

- `help` 的 `q=渐变` 与 `q=图层` 各返回 0 条；`q=背景` 只返回 docx 的 `setPageBackground`。
- `setShapeFill` 只接受 6 位十六进制色值，页面深色底只能用全页矩形充当，落日与沙丘靠 3 层椭圆叠出。
- `insertShape` 的 x 为 -1200000 时报 `InvalidField: x 从 0 起`，半出血形状做不了。
- `inspect` 的 `scope` 传 `shapes` 或 `textBoxes` 都报 `InvalidField: 不认识的字段`，实际只认 `slide` 加 `maxShapes`。
- 474 个 op 的 `apply` 在第 16 条失败时只报 `ops[16].x`，不带对象 `id`、名称或字段路径。
- `help` 摸清 pptx 的 create 契约要 8 次以上往返，一次只展开一层 `$ref`。
- 生成的 pptx 无法在工具内自检，只能用项目外的 macOS Quick Look 拆成单页再拼图检查。

`create`、`inspect`、`apply` 的领域 JSON 契约已经能支撑完整的读写闭环。下面要补的是调用方能不能一次写对、写错了能不能查、页面能不能做得更好看。

## 目标

让调用方一次写出带几何与颜色的页面，提交前能检查布局，失败时能定位到具体对象。范围分三块：调用方自检、pptx 表达力、安装与分发。

## 不做

下列条目与仓库已定约束冲突，本计划不纳入：

- 渲染、导出 PNG 或 PDF、生成缩略图。`docs/architecture.md` 与 `roadmap/pptx.md` 都写明不做渲染；改为只返回几何数据的 `layoutCheck`。
- 放映引擎、任意时间轴树、与 PowerPoint 像素级一致。`roadmap/pptx.md` 的永不做清单保持原样，`setTiming` 继续报 `UnsupportedOp`。
- 排版引擎、按新画布重排。`layoutCheck` 只做估算和提示，不改文件。
- 为 JSON-RPC 信封改领域 JSON 字段、把 `ops` 拆成 MCP 专用工具参数。`AGENTS.md` 禁止。
- 在 `roadmap/` 为命令行 MCP 开格式待做序号。

## 对架构的影响

阶段一只碰 `crates/ooxp/src/help.rs`、`crates/ooxp/src/dispatch.rs`、`crates/ooxp/src/error/` 和新增的只读动作，不动 `opc` 写回，也不改三个动作的语义。

`apply` 的事务性会碰到写回边界。动手前先读 `crates/ooxp/src/dispatch.rs` 与 `crates/ooxp/src/opc/` 的落盘路径，确认当前是逐 op 改内存树后一次写盘，还是每条都写；顶层设计确定后再动代码。

阶段二只在 `crates/ooxp/src/pptx/` 内扩展写入，不新增跨格式引用，不新增 crate，不往 `Cargo.toml` 加三方依赖。稳定 id 规则不变：新 `cNvPr/@id` 仍取该宿主已有最大值加 1。

## 阶段

### 阶段一：调用方自检（不写 XML）

1. 修 `inspect` 的 `scope` 契约不一致。这属于 Bug，按工程原则先在 Debug 模式留下复现证据，包括请求 JSON、返回体和 `docs/json-contract-pptx.md` 对应段落，再决定是删掉 `inspectScope` 里 pptx 不认的字段，还是补实现。
2. `help` 增加一次展开 `$ref` 的能力，或在 `docs/json-schema/` 提供可下载的完整 schema。契约怎么选，先写进 `docs/cli.md`。
3. `apply` 的错误正文带 `ops` 下标、对象 `id`、对象名和字段路径。文案改 `crates/ooxp/src/error/messages/`，`docs/errors.md` 同步。
4. `apply` 的 `dryRun` 与事务性。`dryRun` 只返回会被改动的部件清单，不写盘；失败时全部回滚。
5. 新增只读动作 `layoutCheck`，返回每页形状的包围盒、越界、重叠和文字溢出估算。它不生成图片，不调用 Office。

### 阶段二：pptx 表达力（先探测，再挂序号）

6. 把 `setPageBackground` 扩到 pptx，写 `p:bg`。docx 版已支持纯色、渐变与图片填充，复用它的字段设计。
7. `setShapeFill` 支持 `alpha`、`gradFill` 与 `blipFill`，让形状能有透明度和渐变。
8. `insertShape`、`insertPicture` 支持 `index`、`before` 或 `after` 指定 `spTree` 插入位置；也可以改成独立的 `setZOrder`。create 阶段的 `pictures` 固定写在 `shapes` 之后，调用方目前只能倒推顺序。
9. `insertShape` 放开负坐标，允许形状出界。
10. `pptxShapeCreate` 合并 `insertShape` 的 `x`、`y`、`cx`、`cy`、`prst`、`fill`、`line`，让 create 一步写出带几何的页面。

第 6 到 10 项都要先按 `roadmap/pptx.md` 用 PowerPoint 16.0 另存探测，确认写出的 XML 能被 Office 打开且无 Repair，再挂待做序号。

### 阶段三：安装与分发

11. `README.md` 的 MCP 配置补绝对路径说明。IDE 启动时不继承 shell 的 `PATH`，`"command": "ooxp"` 会找不到可执行文件。
12. 补 crates.io 安装与校验说明。Release 资产走签名跳转，某些网络下 `curl -L` 返回 504，而 `static.crates.io` 可用。
13. 把 `README.md` 里与项目无关的个人内容移到单独文件，并写清 BSL 1.0 的非生产用途边界。

## 验收

本阶段的出口只有这份计划文档。`git status` 只应出现 `.plan/` 下的一个新文件，代码与 `docs/` 都不动。

后续每个阶段按「计划 → 文档 → 实施 → 验证」闭环走，各自的出口条件如下。

- 阶段一：
  - `ooxp mcp` 的 `tools/list` 仍只有原有动作，或加上经确认的 `layoutCheck`。
  - 领域 JSON 已有字段不改名；`help` 返回的 scope 字段与 `inspect` 实际接受的字段一致。
  - `apply` 失败时错误正文带对象 `id`；`dryRun` 不产生文件；`layoutCheck` 不生成任何图片。
- 阶段二：
  - 每份新写入的 XML 用 PowerPoint 16.0 打开无 Repair；`inspect` 的稳定 id 在多次 apply 后不漂移。
  - 负坐标形状能进树；create 单步生成的页面与 create 加 apply 两步生成的结果逐项一致。
- 阶段三：全新环境按 `README.md` 配好 MCP 后，`initialize` 能返回 `serverInfo`。

所有阶段都要跑 `cargo fmt --all`、`cargo clippy --all-targets --all-features -- -D warnings` 和 `cargo test`。涉及 pptx 写入的阶段另按 `docs/checklist-pptx.md` 做 Office 手测。
