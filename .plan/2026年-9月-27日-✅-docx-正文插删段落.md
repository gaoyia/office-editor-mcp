# docx 正文插删段落

状态：✅ 文档、实现、库测试与 Word 16.0 手测已通过  
日期：2026-09-27

从 `roadmap/docx.md` 拆出待做序号 0。`insertPara` / `deletePara` 已在文本框、脚注、尾注、批注内开放；本期扩到主文档、页眉页脚与表格单元格内的 `w:p`。

## 目标

主文档与页眉页脚里的段落能在指定段之后插入、能删除。新段带新的 `w14:paraId`。不整篇重建 `document.xml`。

## 已锁定

- 手术刀：只插删 `w:p`，不插删 `w:tbl` / `w:tr` / `w:tc`，不重写整份 styles。
- `insertPara` 的 `id`：正文段后、`docx:document`（故事末、`w:sectPr` 之前）、页眉/页脚容器末、页眉/页脚段后；框/注/批注原规则不变。
- `deletePara` 必须是段落 id。对 `docx:document`、页眉容器等发 `deletePara` → `InvalidId`。
- 直接父节点只剩一个 `w:p` → `InvalidField`（`LastStoryPara`：正文/页眉/页脚/单元格；框/注/批注仍用原理由）。
- 删收集顺序最后一段且该段 `pPr` 带文档末 `sectPr`：把 `sectPr` 挪到留下的最后一段再删。非末段却带 `sectPr`（分节符）→ `NotImplemented`（`SectionBreakPara`）。
- 段内书签/批注范围/许可范围起止不成对 → `NotImplemented`（`CrossParaMarker`）。
- 段内有 `w:ins` / `w:del` / `w:moveFrom` / `w:moveTo` → `NotImplemented`（`ParaHasRevision`）。
- 页眉页脚用带前缀的段落 id，规则与 `setParaText` 相同。

## 不做

- 自动重编目录、交叉引用
- 修订模式下的「插入修订」（那是修订计划）
- 表格本身的增删行、列、单元格（表格计划）

框内 / 注内 / 批注内插删已过。
