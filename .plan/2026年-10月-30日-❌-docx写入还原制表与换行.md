# docx 写入还原制表与换行

状态：❌ 未开始。
日期：2026-10-30

不在三种格式的待做表里，不占待做序号。来源是 2026-10-30 第二轮代码审计。

排在 2026-10-30 审计拆出的重构计划前面。领域 JSON 字段不变，变的是写出的 XML。

## 目标

docx 文本读写对称：inspect 读成什么，原样写回去，Word 里还是同样的文字和同样的分隔。

`docs/json-contract-docx.md` 第 1631 行规定，inspect 的 `text` 里 `w:tab` 读成 `\t`、`w:br` 读成 `\n`。写入侧现在不对应：

- 实测：create 的段落文本 `a\tb\nc`，写出的是 `<w:t xml:space="preserve">a\tb\nc</w:t>`；`setParaText` 写入同样如此。
- `para.rs` 的 `remove_all_t` 只删 `w:t`，段落里原有的 `w:tab`、`w:br` 留在原处。原来两行的段落改成单行，读回来还多一个 `\n`。

pptx 在 2026-09-26 踩过同一个坑，见 `.bugfix-reports/2026年-9月-26日-✅-pptx-setShapeText-压掉段落并搬错对齐.md`。那份记录的教训已经点名 docx 要处理 `w:tab` 和 `w:br`，写入侧没有落实。

## 不做

- 不改 inspect 的读法。
- 不处理 `w:cr`、`w:noBreakHyphen` 等其余字符元素，除非 inspect 也读它们。做第 1 步时核对。
- 不改 run 级格式。新拆出来的 run 沿用被写入那个 run 的 `w:rPr`。

### 1. 盘点

- 读：inspect 拼 `text` 时进入了哪些元素。至少有 `w:t`、`w:tab`、`w:br`。
- 写，元素树一侧：`para.rs` 的 `set_visible_text`、`rewrite_runs`、`fill_first_run`、`remove_all_t`、`new_text_run`。调用方在 `sdt.rs`、`link.rs`、`comments.rs` 与 `para.rs`。
- 写，字符串拼接一侧：`create.rs` 的段落拼接与 `run_t_xml`，`textbox_ac_xml`，以及注、批注、页眉页脚 create 时拼文本的地方。
- 结果写回本节，作为第 3、4 步的完整清单。

### 2. 文档

在 `docs/json-contract-docx.md` 的 `setParaText` 与 create 段落文本两处写明：

- `\t` 写成 `w:tab`，`\n` 写成 `w:br`，都放在 run 里，与 `w:t` 平级。核对 ECMA-376 §17.3.3 的 `CT_R` 内容模型，写上条款号。
- 替换文本时，旧的 `w:t`、`w:tab`、`w:br` 一起清掉。
- 写入后 inspect 读回的 `text` 等于写入值。

### 3–4. 实现

- 元素树一侧和字符串一侧共用一个「把一段文本拆成 run 子元素」的函数，不要两边各写一份。
- `remove_all_t` 改成清掉所有会进入 `text` 的元素，名字随之改掉。

### 5. 验收

- 写入 `a\tb\nc`，产物是 `w:t`、`w:tab`、`w:t`、`w:br`、`w:t`，读回值等于写入值。
- 原来含 `w:br` 的段落改成单行，产物里没有 `w:br`。
- 单行改多行再改回单行，每一步读回值都等于写入值。
- 样本要用手写的 XML，或 Word 亲手存的文件，不能只用本库 create 的产物。
- `cargo test -p ooxp --lib --tests` 全过。
- `cargo fmt --all` 与 `cargo clippy --all-targets --all-features -- -D warnings` 通过。
- 手测：用 Word 16.0 打开写入 `a\tb\nc` 的产物，看到制表和换行。
