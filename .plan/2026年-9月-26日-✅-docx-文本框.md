# docx 文本框

状态：✅ 文档、实现、库测试与 Word 16.0 手测已通过  
日期：2026-09-26

正文图之后开。文本框是独立节点，框里的段落和图片复用已有 `setParaText` 与图片 op。不做绕排计算。

规范线索：现代 Word 文本框是 DrawingML 的 `wps:wsp` / `wps:txbx`，内容在 `w:txbxContent`（ECMA-376 §20.4，MS-DOCX 的 WordprocessingShape）。常包在 `mc:AlternateContent` 里，只进 Choice。VML `v:textbox` 只出现在 Fallback，不编辑。遇框外的 `w:txbxContent` 仍停住，避免再把框内段落算进宿主 `paraCount`。

## 目标

正文、页眉、页脚里的文本框能查、插、删，能改字、改尺寸、改绕排与粗位置，能改框内段落与图。链接文本框能看见链条，并能断开或接上。

## 稳定 id

框挂在宿主段落上，不挂在节上。页眉页脚框挂在对应容器的宿主段上。

| 节点 | id | 例子 |
| --- | --- | --- |
| 正文框 | `{段落 id}/txbx:{docPrId}` | `para:3F2A1B00/txbx:8` |
| 页眉框 | `{页眉段落 id}/txbx:{docPrId}` | `header:default:1/para:AA/txbx:8` |
| 框内段落 | `{框 id}/para:{paraId}` | `para:3F2A1B00/txbx:8/para:00FF00AA` |
| 框内图 | `{框内段落 id}/pic:{docPrId}` | `para:3F2A1B00/txbx:8/para:00FF00AA/pic:1` |

没有 `docPr/@id` 时用 `txbx:index:{k}`，`k` 只在该宿主段内从 1 计，`stable: false`。组合本身不进树，只展开里面的框。

对宿主段落 id 发框专用 op（除 `insertTextBox`）报 `InvalidId`。对框 id 发 `setParaText` 报 `InvalidId`。拿正文 `para:` 去改框内同 hex 报 `IdNotFound`。

## inspect

- 无 `scope.textBoxes` 时，根上仍给正文 `textBoxCount`（不含页眉页脚）。页眉页脚容器给该部件的 `textBoxCount`。
- `textBoxes: true` 且给了正文切片时，切片段落带 `textBoxes`。只给 `textBoxes`、不切正文：只展开页眉页脚容器上的框，根上不倒出全部正文框。
- 框字段顺序：`id`、`docPrId`、`name`、`kind`、`cx`、`cy`、`wrap`、`link`、`paraCount`、`pictureCount`、`stable`，再按 scope 跟 `paragraphs` / `pictures`。
- 框内段落默认不倒出；`headerFooter` 不管框。框通常短，给了展开框内容的键就返回该框全部段落，不再单独分页。具体键名写进契约时定一个，不要和 `from`/`maxParas` 抢正文。
- 文本框里的段落不再计入宿主 `paraCount`、不进 `outline`（与现行边界一致）。

## apply

允许变脏：宿主部件（主文档或页眉页脚）及其 `.rels`、`[Content_Types].xml`、媒体。不整篇重建。

`setParaText` 进入框内时，仍遇嵌套 `w:txbxContent` 停住。

## 不做

- 排版、自动绕排、艺术字几何、三维、映像
- 编辑 VML Fallback
- 正文（框外）插删段落
- 脚注、尾注、批注里的框：那两份计划已过，注内 / 批注内的框仍不进树。id 前缀已留好，不够用时补进容器计划，不另开模型

## 验收

- Word 另存带行内框、浮动框、组合里的框、链接框；inspect 的 id、`kind`、`wrap`、`link` 对。
- 改框内字、插空框、删框，Word 无修复。
- 尺寸与绕排用 COM 或目视对（允许 EMU 误差）。
- 框内插图、换图与正文图规则相同。
- 改宿主段落文字，框还在。
