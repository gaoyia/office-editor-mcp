# xlsx 共享列几何与尺寸链路

对应 roadmap/xlsx.md 的工作表、迷你图和图表出图既有项；本轮是用户要求的共性缺陷修复，不启动其它待做功能。

## 根因与边界

- Oracle 的屏幕逻辑 DPI 为 106，库契约为 96。Calibri 11 的数字宽从 7 量化为 8，不是精确的 106/96 比例；货币样本 COM 点宽折回 96 后的约 18 像素差不能直接认定为漏 padding。
- 库把所有 Normal 字体当成 MDW=7 是另一项真限制。公开 GDI 的固定 96 实测：Calibri 11=7，Arial/Consolas/等线 11=8，Calibri 14=10；同时核对实际字体名。
- layout 把 OOXML width 经过两位小数 UI 宽度再还原，10.125 会从规范 71 变成 70；defaultColWidth=10 又重复加 padding，从 70 变成 75。
- 本轮只统一只读出图的列上下文，修正 layout 的 Calibri 基线换算；不泛化成全部写入 API 的任意字体布局。图表 zoom、行高 round 与工作表行高 floor 保持原契约，隐藏行/editAs 的其它几何不借本轮盲改。

- [x] 直接 OOXML width 换像素；sheet/tiles/spark/twoCell chart 以及选区之外的列累计使用同一列规则，隐藏列为 0。

- [x] 新增固定 MDW 参数、默认列宽、隐藏列、本地化 Normal、选区外累计和 canonical layout 回归；Windows public API 集成覆盖五档字体字号、sheet/spark/chart、隐藏/非 A1，以及非 A1 Arial 切块整图像素拼接。

## 尚未消除的差异

- 官方 106 与库 96 的行高、图表尺寸和字体量化差仍在；不能逐列加常数或让库跟随用户显示 DPI。
- 人工 Normal 置于非零 style-XF 的探针，Excel16 与库按 XML 解析的字体几何仍需单独查证。本轮不把它归咎于 DPI，也不标官方布局通过。
- sheet 矩阵原图还含内嵌迷你图，工作表 renderer 尚未绘制该内容；这是现有内容残差，不归为 DPI。
- 原始 OOXML width 不套 UI 255 字符上限；UI 255 的存储宽 255.7109375 仍为 1790px（Calibri11/96），避免引入新拒绝。
- 隐藏源迷你图仍按原支持范围 NI；本轮未扩展图形、文字灰阶、透明或额外功能许可。
- 先前 GetBounds Pixel 被误当 Millimeter 的 vector96 图不用于验收。一次错误的 COM Range 枚举 oracle 尝试已单独隔离并标无效；一次剪贴板瞬时错误日志也保留，最终原生导出矩阵单独记录。
