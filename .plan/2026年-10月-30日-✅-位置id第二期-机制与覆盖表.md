# 位置 id 第二期：机制与覆盖表

状态：✅ 已完成。
日期：2026-10-30

不在三种格式的待做表里，不占待做序号。这是 `.plan/2026年-10月-30日-✅-apply开始前固定id.md` 文末「第二期」的第一份，也是后面六份的前置。

## 为什么要做

`docs/json-contract.md`「稳定 id」原来写着：「其余按位置编号的 id 仍会在本批增删后重排。」

调用方是模型：它从 inspect 拿到 id，一次发出一批 op。批里只要先有增删，后面按位置点名的 op 就会落到别的对象上，而且不报错。第一期已经在 docx 段落和 pptx 幻灯片上实测出这个问题，其余位置 id 是同一类。

第一期的教训有两条：

- 找对象的代码散在各模块，只有被测试点到的那几处接上了。
- 回归测试只覆盖了复现时用的那一两种 op。

所以第二期先把机制和覆盖表立起来，再按格式铺开。

## 目标

- 一套通用的「apply 开始时编号」机制，供三种格式的 XML 元素使用。
- 一张覆盖表：三种格式的每个 op 都登记一次，写明它是否接受位置 id、接受哪一族、由哪条回归测试覆盖。
- 一条元测试：`help` 列出的 op 必须都出现在覆盖表里。以后新增 op 不登记，测试就失败。

## 不做

- 不改任何 id 的字符串格式。
- 本份不把任何新的 id 族接上机制。那是后面六份的事。

### 1. 文档

- `docs/json-contract.md`「稳定 id」：按族列出已经固定的，以及还在后续切片里的。每做完一份，就从「还在后续」里删掉对应的族。
- `docs/architecture.md`「元素树」：一个族在 apply 开始、第一次装载部件时编号一次，之后按编号找元素。本批新建的元素不占旧编号。写回时编号属性随 `ooxp:` 前缀一起丢掉。编号不把部件标脏。

### 2. 通用机制

- 放在 `xml.rs`：`pin_tree`、`pin_matches`、`pin_attr`。
- 给定一个根和每个元素怎么走的判定，按文档顺序给成员挂 `ooxp:` 前缀的编号属性。不同族用不同属性名，例如 `ooxp:pin-dv`。空族名是 `ooxp:pin`。
- 查找时按编号属性匹配。编号属性为空，表示本批新建，不占旧编号。没有编号时退回当时数到的位置。
- 只在第一次装载部件时编号，和 docx 段落原来的做法一样。编号只改内存里的属性，不把部件标脏。

### 3. docx 段落

- `docx/para.rs` 的 `pin_paragraph_indexes` 与 `index_matches` 改用通用机制。文本框、脚注、尾注、批注仍各自从 1 起。`AlternateContent` 仍只进第一支。
- `tests/docx_para_index.rs` 六条全过。

### 4. 覆盖表

- `crates/ooxp/tests/id_pin_coverage.rs`：`(格式, op 名, 位置 id 族或「无」, 回归测试名)`。三种格式 477 个 op 各一行。
- 元测试从 `help` 取名单，和表逐个比对。删掉一行，或 help 里多一个未登记的 op，测试失败。
- 第一期已经有回归的 op 写上测试函数名。只走同一套段落或幻灯片查找、没有单独用例的，写「入口同 …」。
- 其余接受位置 id 的 op 标「待第二期」，并写明归哪一份计划。
- `series:{idx}` 跟趋势线、误差线记在同一份计划里。插入趋势线或误差线时，点名的就是系列 id。

### 5. 验收

- 元测试通过。
- `cargo test --workspace` 全过。
- `cargo fmt --all` 与 `cargo clippy --all-targets --all-features -- -D warnings` 通过。
- 不改写出的 XML，没有跑 Office。
