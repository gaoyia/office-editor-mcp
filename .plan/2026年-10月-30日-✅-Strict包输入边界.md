# Strict 包输入边界

状态：✅ 已完成。
日期：2026-10-30

不在三种格式的待做表里，不占待做序号。三种格式共用。

## 现象

`docs/architecture.md` 只写了「对齐 Transitional OOXML，Strict 命名空间只作对照，create 不按 Strict 生成」，没写遇到 Strict 输入时怎么办。

2026-10-30 审计实测：

- 把一份 docx 的 WordprocessingML 和关系命名空间换成 Strict（`http://purl.oclc.org/ooxml/...`）。
- inspect 正常返回段落。代码大多按本地名和关系类型的后缀匹配，所以读得出来。
- 对它 apply `insertHyperlink`，没有报错，但新写的关系类型是 Transitional 的 `http://schemas.openxmlformats.org/officeDocument/2006/relationships/hyperlink`。

结果是同一个包里混着两套命名空间。这种文件库自己读得回来，Word 很可能认不出这条超链接或要求修复。这是静默写坏，比明确拒绝更糟。

## 目标

遇到 Strict 包时，行为是明确、写进文档的，不再静默写出混合命名空间的文件。

## 不做

- 本份不实现 Strict 的写入。真要支持，另开路线图条目。
- 不处理 UTF-16 编码的部件：quick-xml 解析会直接报错，不会静默写坏，而且 Office 只写 UTF-8。

### 1. 规则

写在 `docs/architecture.md`、`docs/opc.md`、`docs/errors.md` 和 docx 分册：

- 识别：根关系里 `officeDocument` 的关系类型，或主部件根元素的命名空间，以 `http://purl.oclc.org/ooxml/` 开头。
- inspect、exportMedia、exportChartData 照常。
- apply 在第一条 op 之前拒绝，报 `NotImplemented`，不写文件。
- create 仍只生成 Transitional。
- Strict 的通用长度（如 `72pt`）在 inspect 时折成 twip。

### 2. 识别

`opc::reject_strict`，三种格式的 apply 在打开包之后立刻调用。

### 3. 拒绝

docx、xlsx、pptx 的 apply 都在执行 op 之前检查。是 Strict 就返回，不把部件标脏，也不写盘。

### 4. 验收

- 三种格式用替换命名空间造出的 Strict 包：inspect 成功，apply 报 `NotImplemented`，另存目标不生成，源文件字节不变。只换关系类型或只换主命名空间也拒绝。
- `42.55pt` 读成 851 twip。
- 2026-10-31 手测 `strict-docx.ps1`。Word 16.0 另存 Strict，`officeDocument` 关系是 `purl.oclc.org`。inspect 成功，页边距按 twip 读出。打开无 Repair。apply 退出码 2，`NotImplemented`，源文件哈希不变，目标文件没有生成。
- `cargo test --workspace` 全过。
- `cargo fmt --all` 与 `cargo clippy --all-targets --all-features -- -D warnings` 通过。
