# docx 导出媒体

状态：❌ 未开始  
日期：2026-09-26

inspect 默认不读媒体字节。调用方要拿到图文件时，按图 id 把 OPC 里的媒体部件原样写出。不做格式转换，不生成缩略图。

规范线索：`a:blip/@r:embed` 经该部件 `.rels` 指向 `/word/media/…`（ECMA-376 §20.2）。

## 目标

已有图 id 能导出为本地文件。领域 JSON 仍不把 base64 当默认载荷。

## 范围

| 序号 | 项 | 状态 |
| --- | --- | --- |
| 1 | 文档先行：新动作或 apply 旁路的字段表、错误、示例、清单 | ❌ |
| 2.1 | `exportMedia`：按图 id 把媒体部件字节写到 `output` | ❌ |
| 2.2 | 页眉、页脚、正文图 id 都认（正文图计划未落地前，正文 id 报 `InvalidId`） | ❌ |
| 2.3 | 文本框 / 脚注 / 尾注 / 批注里的图：容器进树之后同一动作能导出 | ❌ |
| 3.1 | `exportChartData`：嵌入图表若带 embedding 工作簿，按图表 id 写出该 xlsx（图表计划落地后开） | ❌ |
| 4 | 库测试 | ❌ |
| 5 | Word 手测不强制；用文件头与部件字节比对即可 | ❌ |

建议提交顺序：`1 → 2.1 → 2.2 → 4 → 5`。2.3、3.1 跟对应容器计划，不挡 2.1。

## 动作

倾向新动作 `exportMedia`，不要塞进 `inspect` 的树。

| 字段 | 含义 |
| --- | --- |
| `action` | `exportMedia` |
| `path` | 源 docx |
| `id` | 图 id |
| `output` | 本地目标路径 |

成功：写出文件，stdout 给 `ok`、`path`、以及部件里的 Content Type。找不到图报 `IdNotFound`。关系指向外部资源报 `OpcPartMissing`（与现契约一致，不下载 http）。

xlsx / pptx 本期报 `InvalidField`。以后若要导出 pptx 的 `p:pic`，另开，不改本动作字段名。

## 不做

- 默认把字节放进 inspect 树
- 转码、缩放、生成预览（那是渲染）
- 从本地文件「导入媒体但不插图」（插图走 `insertPicture`）

## 验收

- 对页眉图 id 导出，字节与 `/word/media/…` 一致，扩展名与内容类型相符。
- 换图后再导出，得到的是新文件。
- 对段落 id 或不存在的图 id 报错类别对。
