# 打开按声明体积

状态：✅ 已完成。
日期：2026-10-29

不在 `roadmap/docx.md`、`roadmap/xlsx.md`、`roadmap/pptx.md` 的待做表里。这是打开、遍历、写盘和 MCP 读入的边界，不占待做序号。领域 JSON 不增加字段，也不改已有字段的含义。

契约真源仍是 `docs/`。先改文档，再改代码。

## 目标

调用方拿来的文件有多大，就按多大打开。限制只打在两类情况上：声明的解压结果达到压缩后大小的 4096 倍，以及写盘时目标路径已经是一个目录。

## 不做

- 不给 Office 包、`requestPath`、`file`、`sound` 设固定兆字节上限。
- 不给 XML 设层数上限。
- 不把口令圈数改小再拿去比对。
- 不改领域 JSON，不加格式待做序号。
- 不处理重名部件、部件名里的盘符、口令比较的耗时、非字符串 `locale`。

### 1. 文档

`docs/opc.md` 的打开一节写明两条规则。解压读到的字节数不得超过该条目在中央目录里的未压缩大小，计数的是实际读到的字节。声明的未压缩大小达到压缩后大小的 4096 倍时，打开失败，错误码仍是 `OpcOpen`。压缩后大小为 0、声明大小却大于 0 时同样失败。比例跟压缩后的大小一起变，把压缩数据垫大只会按同一比例抬高允许的声明大小。

`docs/errors.md` 的 `OpcOpen` 补上这一条。口令圈数超过上限时走已有的 `NotImplemented`（有哈希但本库不核对），不要写成口令错误。

`docs/cli.md` 写明 MCP 入站一帧最大 256 MiB。一行一条和 `Content-Length` 共用这个上限。`requestPath` 不在这 256 MiB 里。

### 2. 解压

`Package::open_bytes` 读每个非目录条目时按块计数。计数超过中央目录的未压缩大小就返回 `OpcOpen`，不把截断后的字节当成该部件。声明大小与实际流一致的文件照常打开，内存占用等于这些部件的未压缩大小。

比例检查在解压前做，用的是目录里的两个数字。声明的未压缩大小 ≥ 压缩后大小 × 4096 就返回 `OpcOpen`。压缩后为 0 且声明大于 0 时也返回 `OpcOpen`。一份普通工作簿的比例是几倍到一两百倍，远低于 4096。把压缩数据垫到 1 MiB 再声明 16 GiB，比例是 16384，仍然拒绝。

### 3. 遍历

`xml::parse` 已经用堆上的栈，保持不动。`collect_text`、`write_element`，以及 xlsx、docx、pptx 里顺着子元素递归的 `walk_*`，改成堆上的显式栈。不设层数上限。层数变多只占这棵树已经占用的内存。按 id 查找的 `find_*` 和各处局部的 `rec` 仍用调用栈。

### 4. 写盘

`write_atomic` 在改名之前看目标路径。它已经是目录时返回 `Io`，不把它改成 `*.ooxp.bak`。目标是已有文件时，仍按现在的临时文件、备份、改名来写。

### 5. 列号与行号

Excel 的列上限是 16384，行上限是 1048576，`xlsx/layout.rs` 里已有这两个常数。`col_origin_emu` 不得对超过列上限的列做 `1..col` 累加。`read_marker` 从包内 XML 读出的列、行超过上限时返回 `XmlBroken`，不得先铸成一个更大的 `u32`。请求里的列、行仍走 `a1` 已有的范围检查。

### 6. 口令圈数

xlsx、docx、pptx 新写的哈希仍是 100000 圈。核对已有哈希时，圈数小于或等于 1000 万就按文件里的圈数算。超过 1000 万则不跑循环，按已有的「有密码但本库不能核」返回 `NotImplemented`，不要当成口令错误。`inspect` 和不带口令的打开不跑这个循环。

### 7. MCP 帧

`read_message` 在按 `Content-Length` 分配之前拒绝超过 256 MiB 的声明长度。一行一条读到超过 256 MiB 同样停止。这是标准输入上的一帧，不是 Office 文件的体积。超过时按协议错误结束这条读取，不把半截正文交给库。`requestPath` 指向的文件有多大就读多大。

### 8. 媒体路径

`host_files` 现在会在校验操作之前，把 JSON 里每个 `file` 和 `sound` 都读进内存。改成确认这条操作确实要这些字节之后再读。读的时候按磁盘上的文件长度，不另设上限。

## 验收

- 声明大小与实际未压缩大小一致、且声明大小小于压缩后大小 4096 倍的包能打开，包括很大的文件。
- 声明的未压缩大小达到压缩后大小 4096 倍的条目返回 `OpcOpen`。压缩后为 0 且声明大于 0 时同样返回 `OpcOpen`。解压输出超过声明大小时也返回 `OpcOpen`。
- 深层元素树可以解析并遍历，进程不因调用栈崩溃。
- 目标路径是目录时，目录还在，函数返回 `Io`。
- 列号大于 16384 时不会按该列号做循环。
- 圈数大于 1000 万时不进入哈希循环，返回 `NotImplemented`。圈数为 100000 的核对结果与现在相同。
- `Content-Length` 大于 256 MiB 时不按该长度分配。`requestPath` 仍按文件实际长度读取。
