# XML 写出收尾

状态：❌ 未开始。
日期：2026-10-30

不在三种格式的待做表里，不占待做序号。来源是 2026-10-30 第二轮代码审计。领域 JSON 不变。

前置：「属性值换行写成字符引用」已完成。两份都改 `xml.rs`，不要同时做。

## 目标

收掉元素树和字符串拼接 XML 这一层剩下的三处问题。

## 不做

- 不改未脏部件。它们按原字节搬，不受影响。
- 不支持 UTF-16 编码的部件。Office 只写 UTF-8，另行评估。

### 1. 注释与处理指令

- 现状：`xml::parse` 第 429 行丢掉 `Comment`、`PI`、`DocType`，部件一旦变脏，写回时这些就没了。这违反「不认识的东西原样保留」。
- 改法：`Node` 加一种原样保存的节点，解析时收下注释和处理指令，写回时原样写出。
- `Node::Text(_) =>` 的穷尽匹配全库有 70 处，逐个判断新节点该当成什么：大多数等同于「不是元素」，`text_content` 不收它。
- 先在 `docs/architecture.md` 的「元素树」一节写明。

### 2. DOCTYPE

- OPC 对部件里出现 DTD 有明确要求。先查 `standards/md` 里 ECMA-376 Part 2 的对应条款，写进 `docs/opc.md`。
- 按条款决定：报 `XmlBroken`，还是保留。不要静默丢掉。

### 3. `Document`

- `Document` 已经实现了 `Drop`，字段本来就不能移出，根节点再包一层 `ManuallyDrop` 没有作用。
- `take_root` 和 `Drop` 里的三处 `unsafe` 都可以改成 `std::mem::replace`，换一个空元素进去，再把交出来的根拆掉。
- `docs/architecture.md`「元素树」一节说「根放在 `ManuallyDrop` 里」的理由不成立，同步改写。
- 顺带核对：`take_root` 有 31 处调用，交出去的 `Element` 离开作用域时仍按层递归析构。深树会不会在这些地方栈溢出，用 8000 层的测试树确认。会的话，给 `Element` 补同样的堆上释放。

### 4. chartex 数值点

- `chart/chartex.rs` 第 107 行：数值系列的点值 `{t}` 直接拼进 XML，没有转义。字符串值会原样进去。
- 改成数值系列只接受数字，在请求解析处校验。或者至少按文本转义。查 `json-contract` 里 chartex 数据的规定再定。

### 5. 测试

- 带注释和 `<?mso-…?>` 处理指令的部件，改其中一个元素后，注释和处理指令的字节还在。
- 8000 层深的元素树：解析、`take_root`、丢弃，都不栈溢出。
- chartex 数值系列给字符串：按第 4 步的决定报错，或者写出的 XML 合法。
- `cargo test -p ooxp --lib --tests` 全过。
- `cargo fmt --all` 与 `cargo clippy --all-targets --all-features -- -D warnings` 通过。
- 手测：用 Excel 16.0 打开一份改过的、带注释的 xlsx，能打开、不报修复。
