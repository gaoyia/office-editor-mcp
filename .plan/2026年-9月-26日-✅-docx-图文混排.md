# docx 页眉页脚图文混排

状态：✅ 文档、实现、库测试与 Word 16.0 手测已通过  
日期：2026-09-26

从第一期暂缓项里拆出「页眉页脚图文混排」。全部能力写在本计划，按编号分期提交。每一期仍是：先改当期 `docs/`，确认后再动代码。正文复用同一套 id / op 暂缓，不挡 2–4。

规范线索：Word 图在 `w:drawing` 里，行内是 `wp:inline`，浮动是 `wp:anchor`（ECMA-376 §20.4）；像素在 `a:blip/@r:embed`，经该部件 `.rels` 指到 `/word/media/…`（§20.2）。`wp:docPr/@id` 作稳定 id。只认 DrawingML 的 `pic:pic`。VML / `w:pict`、图表、SmartArt、文本框不做。`mc:AlternateContent` 仍只进 Choice。

## 目标

页眉、页脚里的图能查、换、插、删，并能改尺寸和绕排。正文以后复用同一套 id 与 op，不另开模型。

本期计划不按全量验收。当前能交的只是表里标着要做、且当期已 ✅ 的编号。

## 稳定 id

图挂在页眉/页脚容器上，不挂在节上。

| 节点 | id | 例子 |
| --- | --- | --- |
| 图 | `{容器}/pic:{docPrId}` | `header:default:1/pic:1` |

`{docPrId}` 取该 `w:drawing` 里 `wp:docPr/@id` 的原文。同一部件内重复 id 时，inspect 都列出，apply 命中文档顺序第一处。没有 `docPr/@id` 时用 `{容器}/pic:index:{k}`，`k` 只在该部件内从 1 计，树上 `"stable": false`。

正文以后用 `para:{paraId}/pic:{docPrId}`，本期不实现。对容器 id（没有 `/pic:`）发图片 op 报 `InvalidId`。对正文段落 id 发 `insertPicture`，或对 `para:…/pic:…` 发其它图片 op，报 `InvalidId`。
