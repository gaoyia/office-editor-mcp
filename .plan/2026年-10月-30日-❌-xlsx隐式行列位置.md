# xlsx 隐式行列位置

状态：❌ 未开始。
日期：2026-10-30

不在三种格式的待做表里，不占待做序号。来源是 2026-10-30 第二轮代码审计。领域 JSON 不变。

## 现象（读代码得到，还没有实测）

ECMA-376 允许 `<row>` 不写 `r`、`<c>` 不写 `r`，位置按前一个兄弟递推（§18.3.1.73 `row`、§18.3.1.4 `c`，动手时核对条款号）。代码里有两处没有处理：

- `xlsx/inspect.rs` 第 607 行：格子没有 `r` 就 `continue`，这些格子在 inspect 树上看不见。
- `xlsx/apply.rs` 的 `find_row_insert_pos` 把没有 `r` 的行当成第 0 行；`find_cell_insert_pos` 跳过没有 `r` 的格子。新行可能被追加到末尾，行序因此乱掉；`setCell` 也可能插出一个重复的格子。

## 不做

- 不给没点名的行和格子补写 `r`。
- 不改行内或行间的顺序。

### 1. 复现

- 手写一张表：前三行不写 `r`，每行三个不写 `r` 的格子。
- inspect `A1:C3`，看看能读到几格。
- `setCell` 写 B2 和 A5，看产物里的行序和格子。
- 复现不出来，就把本计划标成 🚫，写明原因。

### 2. 文档

在 `docs/json-contract-xlsx.md` 的单元格一节写明：

- 没有 `r` 的行和格子按前一个兄弟递推位置，第一个默认为 1 或 A。
- `setCell` 写进这样的行时，新格子写上 `r`，已有的格子不补。

### 3. 实现

- 写一个按顺序产出（行号或列号，节点）的遍历，`inspect.rs` 和 `apply.rs` 都用它，不要两边各推算一份。
- 和「setCell 按表建一次索引」那份计划改的是同一批函数，两份不要同时做。先做的一份把这个遍历留好。

### 4. 验收

- 第 1 步的样本：inspect 读到 9 格，A1–C3 位置正确。
- `setCell` 写 B2 改的是原有那一格，写 A5 时新行插在正确位置，行序升序。
- 样本必须手写，不能用本库 create 的产物。create 一定会写 `r`。
- `cargo test -p ooxp --lib --tests` 全过。
- `cargo fmt --all` 与 `cargo clippy --all-targets --all-features -- -D warnings` 通过。
- 手测：用 Excel 16.0 打开第 4 步 `setCell` 的产物，不报修复，数值在对应的格子里。
