# 属性值换行写成字符引用

状态：❌ 未开始。
日期：2026-10-30

不在三种格式的待做表里，不占待做序号。这是缺陷修复，记录见 `.bugfix-reports/2026年-10月-30日-❌-XML写回丢掉属性里的换行.md`。

排在 2026-10-30 审计拆出的重构计划前面。领域 JSON 不变。

## 目标

脏部件写回时，属性值里的 TAB、LF、CR 写成 `&#9;`、`&#10;`、`&#13;`，文本节点里的 CR 写成 `&#13;`。读进来是什么，写出去 Office 读到的还是什么。

## 不做

- 不改未脏部件的写法。它们仍按原字节搬。
- 不处理非法控制字符。那是另一份计划「请求拒绝非法 XML 字符」。
- 不改 quick-xml 版本。

### 1. 文档

`docs/architecture.md` 的「元素树」一节补一条：

- 写回属性值时，`<`、`&`、`"` 之外，TAB、LF、CR 写成字符引用。理由是 XML 1.0 §3.3.3 的属性值规整。
- 写回文本时，CR 写成字符引用。理由是 XML 1.0 §2.11 的行尾处理。

### 2. `write_element`

- 属性：先按上面的规则转义成字符串，再以「已经转义」的形式交给 quick-xml，避免它再转一遍。动手前先确认 0.37.5 里哪个构造方式不做二次转义，写进本节。
- 文本：同理，用已经转义的形式写出。
- `xml.rs` 里加一个私有转义函数，属性和文本各用一套字符集。

### 3. 字符串拼接

- `escape_attr` 加上 TAB、LF、CR。
- `escape_text` 加上 CR。
- 这两个函数有 49 处调用，都是 create 或插入时拼 XML 用的。改完以后，create 写出的多行属性也随之正确。

### 4. 回归测试

- `xml.rs` 单测：`<a x="1&#10;2&#9;3&#13;4">a&#13;b</a>` 解析再写回，字节里仍是这些字符引用。
- xlsx 保真：数据验证 `prompt` 带 `&#10;`，只改同表另一格，产物字节里仍是 `&#10;`。
- pptx 保真：图片 `descr` 带 `&#10;`，改同一页某个形状的文字，`descr` 字节不变。
- `cargo test -p ooxp --lib --tests` 全过。
- `cargo fmt --all` 与 `cargo clippy --all-targets --all-features -- -D warnings` 通过。

### 5. 手测

- 用 Excel 16.0 打开第 4 步的 xlsx 产物，选中 A1，数据验证提示是两行。
- 用 PowerPoint 16.0 打开第 4 步的 pptx 产物，图片的替代文字是两行。
