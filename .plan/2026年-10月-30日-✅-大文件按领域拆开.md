# 大文件按领域拆开

状态：✅ 已完成。
日期：2026-10-30

不在三种格式的待做表里。这是源文件怎么放，不占待做序号。领域 JSON 不增加字段，也不改已有字段。

契约真源仍是 `docs/`。先改 `docs/architecture.md`，再搬代码。搬的是函数所在的文件，不是操作的语义。

## 目标

`apply` 仍是该格式的唯一入口。`match` 留在 `apply.rs`。各操作的函数体放到该对象已经所在的模块。调用方看到的行为不变。

本份只动 `crates/ooxp/src/docx/apply.rs`（7137 行）。`pub fn apply` 的 `match` 大约在第 85 行到第 778 行，后面六千多行是各操作的函数体。

## 不做

- 不改 op 的语义、id 或错误码。
- 不改领域 JSON。
- 不拆 `error/kind.rs` 和 `error/messages/`。那是穷尽的错误枚举和文案，按语言分文件已经够了。
- 不按行数切开测试夹具。`tests/docx_fidelity.rs` 里的大段 XML 留在原处。
- 不再加 `create_roundN` 这种按批次命名的文件。
- 本份不搬下面这些文件。它们另开计划，顺序写在文末。

### 1. 文档

在 `docs/architecture.md` 里 `request/` 那一段后面补上：

- `apply.rs` 只做打开包、按 op 分发、写回脏部件。
- 某个对象已经有模块时，这个 op 的函数体放在那个模块，不堆在 `apply.rs`。
- 多个对象都要用的部件装载留在 `apply.rs`，不在每个模块各抄一份。

### 2. 搬哪些

按函数名前缀搬，不改函数在做什么。

- 超链接：`link.rs`、`drawing_hlink.rs`
- 段落正文与 run：`para.rs`
- 段落和 run 的格式：`format.rs`
- 表格：`tbl.rs`
- 图：`picture.rs`
- 文本框、形状、连接线、组合：已有的 `textbox.rs`、`shape.rs`、`connector.rs`、`group.rs`
- 批注：`comments.rs`
- 脚注尾注：`notes.rs`
- 页眉页脚、节、页边距：`hf.rs`、`sect.rs`
- 域、编号、样式、公式、内容控件、修订：对应的已有模块

搬过去的函数改成 `pub(crate)`，让 `apply.rs` 的 `match` 还能调用。参数和返回值保持原样。对象模块里原来已有同名函数时，原函数去掉 `apply_` 前缀，op 函数仍用原名。

### 3. 留下什么

`apply.rs` 留下：

- `pub fn apply`
- 对 `DocxOp` 的 `match`
- 多个对象共用的装载，例如按部件取出已解析的文档、标脏

`match` 的每一支仍然调用原来的函数，只是函数换了模块。

### 4. 验收

- `cargo test -p ooxp --lib --tests` 里 docx 相关测试通过。不要求 Office。
- `cargo fmt --all` 与 `cargo clippy --all-targets --all-features -- -D warnings` 通过。
- 搬完后 `docx/apply.rs` 不再装着某一类对象的整段实现。
