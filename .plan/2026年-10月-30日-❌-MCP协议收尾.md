# MCP 协议收尾

状态：❌ 未开始。
日期：2026-10-30

不在三种格式的待做表里。`mcp` 模式只在 `.plan/` 记账。领域 JSON 不变。

## 现象

2026-10-30 审计时读 `crates/ooxp-cli/src/mcp.rs` 并实测，有三处和协议或文档对不上：

- **不以 `{` 开头的行被静默丢掉。** `read_message` 跳过既不以 `{` 开头、也不是 `Content-Length:` 的行。实测发一行乱码，收不到任何回复。`docs/cli.md` 第 117 行写的是「JSON-RPC 解析失败仍是 `-32700`」。
- **批量请求被静默丢掉。** 以 `[` 开头的 JSON-RPC 批量请求走的也是上面那条路，不回任何东西。
- **`initialize` 原样回显客户端的 `protocolVersion`。** 客户端发什么版本，就回什么版本，等于声称支持所有版本，包括本程序没实现的行为（比如某些版本要求的批量请求）。

## 不做

- 不改六个工具的参数，不改领域 JSON。
- 不新增 MCP 能力（资源、提示词等）。

### 1. 文档

先在 `docs/cli.md` 定下：

- 一行一条的模式里，任何非空行都当作一条消息。解析不了就回 `-32700`，`id` 为 `null`。
- 批量请求：二选一，写进文档。
  - 支持：逐条处理，按 JSON-RPC 2.0 回一个数组，通知不进数组。
  - 不支持：回 `-32600`（Invalid Request），`message` 说明不收批量请求。
  - 倾向不支持：协议较新的版本已经去掉了批量，而且六个工具都是一次一条请求。
- 版本协商：列出本程序支持的协议版本。客户端请求的版本在名单里就回它，不在就回名单里最新的一版。查 MCP 规范确认每个版本对服务端的要求，写进文档。

### 2–4. 实现

- `read_message`：不再跳过非空的非 JSON 行，交给 `reply_with_lang` 回 `-32700`。
- 批量：按第 1 步的决定处理。
- `initialize`：按支持名单协商版本。

### 5. 测试

- 发一行乱码，回 `-32700`，`id` 为 `null`。
- 发一个批量请求，按文档的决定得到对应的回复。
- `initialize` 请求名单里的版本，回同一版本；请求一个不认识的版本，回名单里最新的一版。
- `--lang en` 时，上面这些错误的 `message` 是英文。
- `cargo test --workspace` 全过。
- `cargo fmt --all` 与 `cargo clippy --all-targets --all-features -- -D warnings` 通过。
- 不改写出的 Office 内容，不要求 Office。
