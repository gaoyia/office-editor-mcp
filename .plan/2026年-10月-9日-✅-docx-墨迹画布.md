## 探测结论（Word 16.0）

写入只走 **`wpc` 画布 + `w14:contentPart` + InkML 部件**。独立 `wordprocessingInk` / `wpi:contentPart` 会被 OpenAndRepair 成未保存的「文档1」，SaveAs2 文件缺失，不作为写入路径。inspect 若文件里已有这种 markup，仍认 `contentPart` + InkML 部件。

空 `wpc`（只有 `bg` / `whole`）COM 是 Type=20、Name=`Canvas 1`，不算墨迹画布，不进本期名单。

`wpc` + `w14:contentPart` + InkML（变体 `wpc-ink`）Word 接受并另存。COM 在 `Shapes` 上 `Type=20`（`msoCanvas`），`Name=Ink Canvas 1`，144×72 磅。XML 虽是 `wp:inline`，`InlineShapes.Count` 仍为 0。包内：

- `[Content_Types].xml`：`Override PartName="/word/ink/ink1.xml" ContentType="application/inkml+xml"`
- 关系：`Type=…/customXml`，`Target=ink/ink1.xml`
- Choice `Requires="wpc"`，Fallback 必须有子元素：空白 `<w:pict/>`
- 画布 `wp:docPr` 与 contentPart `cNvPr` 是两个 id
- Word 会改写 InkML（压缩 trace、补 channelProperties / timestamp）；库插入用规范最小 InkML 即可

探测弹窗不是这条 XML 坏了：

- 安全模式：探测脚本 `Stop-Process -Force` 杀 Word，Word 当成崩溃。不要再强杀。
- 另存为：探测文件写在 `%TEMP%`，收尾只认 `manual-check/office/out`；独立 `wpi` 变体修成「文档1」。

命名空间：

- `wpc`：`http://schemas.microsoft.com/office/word/2010/wordprocessingCanvas`
- `w14`：`http://schemas.microsoft.com/office/word/2010/wordml`（画布里的 contentPart 是 **w14**）
- `wpi`：`http://schemas.microsoft.com/office/word/2010/wordprocessingInk`（另存会声明，写入 Choice 不走这条 URI）
- InkML：`http://www.w3.org/2003/InkML`
- `mc:Ignorable` **不要**把未声明的 `w15` 写进去

MS-ODRAWXML 的 `isComment` 默认 true；Word 另存的 body 画布没写该属性，COM 仍是 Type=20。写入不必强塞。

## 已锁规则

- 只认 **docx**。xlsx / pptx 上 `scope.inkCanvases` 与这些 op 报未知字段 / `InvalidField`。
- 判定：DrawingML 里本地名为 `contentPart` 的节点，关系目标部件 Content Type 为 `application/inkml+xml`，或根为 InkML `ink`。空 `wpc` 不算。
- 正文 + 页眉页脚。遇 `w:txbxContent` 停住。注内 / 批注内 / 框内本期不编；`insertInkCanvas` 对注/批注段落报 `GraphicInRestrictedStory`，对框内段落报 `InvalidId`。
- 组合 `wpg:wgp` 本身不进树；里面的 ink contentPart 展开。`groupShapes` **不收** 墨迹成员。
- `mc:AlternateContent` 只进 Choice。不编辑 VML Fallback；删时整段 AlternateContent 带走。
- **id**：`{段落 id}/ink:{cNvPr 或外层 docPr}`，没有则 `/ink:index:{k}`，`stable: false`。优先 contentPart 的 `cNvPr/@id`。
- inspect：根上始终 `inkCanvasCount`（只计正文）。字段顺序插在 `connectorCount` 之后。`scope.inkCanvases: true` 才出名单。每条：`id`、`name`、`kind`、`cx`、`cy`、`wrap`、`contentType`（`application/inkml+xml`）、`stable`。不把 InkML 原文摊进树。
- apply：
  - `insertInkCanvas`：`id` 为正文或页眉页脚段落；`file` 必填（InkML）；`cx`/`cy` 成对可选，默认 `1828800`×`914400`。写入 wpc 画布 + w14:contentPart + InkML 部件，`Requires="wpc"`，Fallback `<w:pict/>`。部件 `/word/ink/inkN.xml`。关系 Type `customXml`。`wp:docPr/@name` 用「墨迹画布 {id}」。
  - `replaceInkCanvas`：换 InkML 字节，保留 drawing 与关系 id。
  - `deleteInkCanvas`：删该 contentPart；若宿主 `wpc` 只剩 bg/whole 则删整段 drawing/AC；关系无人引用则删部件与 Override。
- `exportMedia`：认墨迹 id，写出 InkML 原字节，`contentType` 为 `application/inkml+xml`。
- create：`paragraphs[].inkCanvases[]`（页眉页脚段同样），每项 `file`，可选 `cx`/`cy`，create 后再走同一套 insert。
- 文件校验：根本地名 `ink`，命名空间 `http://www.w3.org/2003/InkML`；否则 `InvalidField`（`InvalidInkMl`）。
- 不改批注墨迹（C3）。不识别成字。不编 VML 墨迹。
