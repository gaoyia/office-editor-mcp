# Strict 包输入边界

状态：❌ 未开始。
日期：2026-10-30

不在三种格式的待做表里，不占待做序号。三种格式共用。

## 现象

`docs/architecture.md` 只写了「对齐 Transitional OOXML，Strict 命名空间只作对照，create 不按 Strict 生成」，没写遇到 Strict 输入时怎么办。

2026-10-30 审计实测：

- 把一份 docx 的 WordprocessingML 和关系命名空间换成 Strict（`http://purl.oclc.org/ooxml/...`）。
- inspect 正常返回段落。代码大多按本地名和关系类型的后缀匹配，所以读得出来。
- 对它 apply `insertHyperlink`，没有报错，但新写的关系类型是 Transitional 的 `http://schemas.openxmlformats.org/officeDocument/2006/relationships/hyperlink`。

结果是同一个包里混着两套命名空间。这种文件库自己读得回来，Word 很可能认不出这条超链接或要求修复。这是静默写坏，比明确拒绝更糟。

## 目标

遇到 Strict 包时，行为是明确、写进文档的，不再静默写出混合命名空间的文件。

## 不做

- 本份不实现 Strict 的写入。真要支持，另开路线图条目。
- 不处理 UTF-16 编码的部件：quick-xml 解析会直接报错，不会静默写坏，而且 Office 只写 UTF-8。

### 1. 规则

建议如下，先写进 `docs/architecture.md`、`docs/opc.md` 与 `docs/errors.md`：

- 识别：根关系里 `officeDocument` 的关系类型、或主部件根元素的命名空间是 `http://purl.oclc.org/ooxml/` 开头，就是 Strict 包。
- inspect、exportMedia、exportChartData：照常执行。它们只读，不写包。
- apply：拒绝，不写文件。错误码用 `NotImplemented`，文案说明本程序只写 Transitional，请先用 Office 另存为 Transitional。
- create：本来就只生成 Transitional，不受影响。

如果用户决定连 inspect 也拒绝，或者要支持 Strict 写入，在这一步改，后面照改。

### 2. 识别

- 放在 `opc`，或三种格式打开包之后的公共入口。三种格式共用一个判定函数，不要各写一份。
- 对照 ECMA-376 Part 1 §9 与 Strict 命名空间表，把 Strict 的关系类型前缀和主命名空间写成常量。

### 3. 拒绝

三种格式的 apply 在执行第一条 op 之前检查，是 Strict 就报错。

### 4. 测试与手测

- 三种格式各造一份 Strict 包（替换命名空间即可）。
  - inspect 正常返回。
  - apply 报 `NotImplemented`，目标文件没有生成，源文件没有变化。
- Transitional 包的全部现有测试不受影响。
- 手测：用 Word 16.0「另存为 Strict Open XML 文档」得到一份真的 Strict docx，确认识别得出来，apply 被拒绝。
- `cargo test --workspace` 全过。
- `cargo fmt --all` 与 `cargo clippy --all-targets --all-features -- -D warnings` 通过。
