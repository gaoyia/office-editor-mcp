# docx 批注

状态：✅ 已通过 Microsoft Word 16.0（`docx-comments.ps1`，8 PASS / 0 FAIL）
日期：2026-09-26

批注是标注，不是正文段落。本期做查、改字、插入、删除、回复、标记完成。不做批注气泡排版。

规范线索：ECMA-376 §17.13。内容在 `/word/comments.xml` 的 `w:comment`（`w:id`、`w:author`、`w:date`、`w:initials`）。主文档用 `w:commentRangeStart` / `w:commentRangeEnd` / `w:commentReference` 成对标定范围。Word 2013 以后还有 `commentsExtended.xml`（完成、父批注）、`people.xml`、以及更新的 commentsIds / commentsExtensible。`commentEx/@paraId` 是该批注**最后一段**的 `w14:paraId`（MS-DOCX §2.5.3.1），不是第一段，也不是宿主段落。

契约真源：`docs/json-contract.md`、`docs/json-schema/request.schema.json`、`docs/errors.md`、`docs/architecture.md`、`docs/opc.md`、`docs/checklist-docx.md`（Cmt1–Cmt7）。

## 目标

批注能列、读、改字，能按段落范围插入，能删，能回复成线程，能标完成。批注里的图复用图片 op。

Word 16.0 的 `Comments` 集合只收带范围标记的批注。`Replies.Add` 会在父范围上再套一套 `commentRangeStart` / `End` / `commentReference`（start 紧跟父 start 之后，end 与 reference 紧跟父 reference run 之后）。不写这套标记时审阅窗格看不见回复。线程关系仍靠 `commentEx/@paraIdParent`。

## 已锁定（写入契约，实现时不要改）

- id：`comment:{w:id}`；批注内段 / 图带此前缀。
- 根上始终有 `commentCount`；名单只在 `scope.comments: true` 时出现。
- 回复在宿主里套一套与父批注相同的范围标记（Word 16 `Replies.Add` 如此）；inspect 读到自己的标记就用，没有则沿用线程根；`deleteComment` 级联删子回复。
- `insertComment` 不提供字符偏移：`start` 段 `pPr` 之后写 `commentRangeStart`，`end` 段内容之后写 `end` + `commentReference`。
- `create` 不写批注。xlsx / pptx 的 `scope.comments` 与批注 op 报 `InvalidField`。
- 墨迹批注 `kind: "ink"`，除 `deleteComment` 外报 `NotImplemented`。

## 验收

- Word 另存带两条批注、一条回复；inspect 的作者、范围、`parent`、`done` 对。
- 改批注字、插入新批注、删除后 Word 无修复；审阅窗格里条数对。
- 标记完成后 COM 或 Word UI 显示已解决。
- 批注内插图无修复。
- 只改批注文本时，未点名的正文段落字节按「范围标记未动」验收。
