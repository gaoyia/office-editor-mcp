## 探测结论（Word 16.0）

`InlineShapes.AddPicture` 插入本地 SVG 后另存：包里同时有 `/word/media/image1.png` 与 `/word/media/image2.svg`。两条关系 Type 都是 `…/image`。

`[Content_Types].xml` 增加：

- `Default Extension="png"` → `image/png`
- `Default Extension="svg"` → `image/svg+xml`

正文 drawing（页眉同一套）：

```xml
<a:blip r:embed="rId6">
  <a:extLst>
    <a:ext uri="{96DAC541-7B7A-43D3-8B79-37D633B846F1}">
      <asvg:svgBlip xmlns:asvg="http://schemas.microsoft.com/office/drawing/2016/SVG/main" r:embed="rId7"/>
    </a:ext>
  </a:extLst>
</a:blip>
```

`a:blip/@r:embed` 指向 PNG 后备。`asvg:svgBlip/@r:embed` 指向 SVG 原件。没有 `mc:AlternateContent`。`mc:Ignorable` 不含 `asvg`。命名空间写在 `svgBlip` 元素上。

探测样例：SVG 根 `width="96"` `height="48"`，`wp:extent` 为 `914400×457200` EMU（96 dpi）。Word 自己的 PNG 后备是 192×96（约 2 倍像素）。COM `Type=17`，宽高 72×36 磅。

库写入用 1×1 PNG 占位作后备。Word 16.0 打开仍认成 SVG：`Type=17`，72×36 磅，标题栏无 Repair。

## 写入规则（锁）

- 文件头认 SVG：BOM / 空白之后能看到 `<svg` 标签。不认 SVGZ。xlsx / pptx 仍只认位图。
- 插入 / create：写 1×1 PNG 占位作 `a:blip` 后备（与 OLE 预览同一张），再写 SVG 原字节。两条 image 关系。`svgBlip` 的 URI / 命名空间与探测一致。不把 SVG 栅格化。
- `cx` / `cy` 都省时：根元素 `width` / `height`（无单位或 `px` 当 CSS 像素，96 dpi）；没有则 `viewBox`；再没有则 1 英寸见方。
- `replacePicture` 换成 SVG：保留已有 `a:blip` 后备图，只加或改 `svgBlip` 与 SVG 部件。`a:blip/@r:embed` 的关系 id 不变。
- `replacePicture` 换成位图：按原规则换 `a:blip` 媒体，去掉 `svgBlip`；SVG 部件无人引用则删。
- `deletePicture`：PNG 与 SVG 两条关系、两个媒体都按无人引用再删。
- `exportMedia`：有 `svgBlip` 时写出 SVG 原字节，`contentType` 为 `image/svg+xml`。没有则仍走 `a:blip`。
- inspect：图仍走现有 id。有 `svgBlip` 时名单末尾多一个 `contentType`，值为 `image/svg+xml`。位图图没有该字段。不把 SVG 原文放进树。

## 不做

- 把 SVG 渲染成位图（Word 自己的 Fallback 除外；库只写 1×1 PNG 占位）
- 在 inspect 树里放 SVG 原文
- 编辑 VML / `w:pict`
- xlsx / pptx 本期不跟
