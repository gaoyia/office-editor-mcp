## 稳定 id

图挂在它所在的正文段落上，不挂在节上，也不挂在文档根上。

| 节点 | id | 例子 |
| --- | --- | --- |
| 正文图 | `{段落 id}/pic:{docPrId}` | `para:3F2A1B00/pic:1` |
| 无 `docPr/@id` | `{段落 id}/pic:index:{k}` | `para:3F2A1B00/pic:index:2` |

`{docPrId}` 取该 `w:drawing` 里 `wp:docPr/@id` 的原文。同一段内重复 id 时，inspect 都列出，apply 命中该段文档顺序第一处。没有 `docPr/@id` 时的 `{k}` 只在该段内从 1 计（该段里所有被收入的图，不只是缺 id 的那些），树上 `"stable": false`。

页眉页脚图 id 不变，仍是 `{容器}/pic:…`。

`insertPicture` 的 `id` 可以是正文段落 id，也可以是页眉或页脚段落 id。对图 id、容器 id 或 `section:{n}` 发 `insertPicture` 报 `InvalidId`。对段落 id、容器 id 或 `section:{n}` 发其余四个图片 op 报 `InvalidId`。

## inspect

- 文档根始终有 `pictureCount`，只计主文档里被收入的图，不含页眉页脚。
- 给了 `from` 与 `maxParas` 时，切片里每段始终有 `pictureCount`。
- `scope.pictures: true` 且给了正文切片时，切片里每段再带 `pictures`。不读媒体字节。
- 只给 `pictures: true`、不给 `from` / `maxParas`：只展开页眉页脚容器上的 `pictures`，根上不挂正文图名单。
- 页眉页脚段落节点仍不带 `pictureCount` / `pictures`。

## apply

五个 op 的字段表与页眉页脚期相同。正文路径脏主文档 XML、主文档 `.rels`、`[Content_Types].xml`，以及新媒体或被删的 `/word/media/…`。

`setParaText` 第 1 条已写「绘图都留着」。本期补测试：该段有图时改字，图还在。

## 验收

- B1：无 scope 时根上有 `pictureCount`、没有正文 `pictures`；`from`+`maxParas`+`pictures` 时目标段有图 id，`kind` / `wrap` 对。
- B2：`replacePicture` 后 Word 无修复；位置与绕排不变。
- B3：`insertPicture` 往正文段落插行内图，Word 能看见且无修复。
- B4：`deletePicture` 后该图消失，Word 无修复。
- B5：`setPictureSize` 后 COM 或目视尺寸对上（允许 EMU 换算误差）。
- B6：`setPictureWrap` 把行内改成浮动 `square` 后，Word 按四周型显示。
- B7：对该段 `setParaText` 后文字已改、图还在。
