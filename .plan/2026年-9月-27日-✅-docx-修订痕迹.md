# docx 修订痕迹

状态：✅ 已通过 Word 16.0 手测  
日期：2026-09-27

从 `roadmap/docx.md` 拆出待做序号 0。inspect 可见文本会跳过 `w:del`。不能列出修订，也不能接受或拒绝。

## 目标

inspect 能按范围列出插入、删除、属性修订。apply 能接受或拒绝被点名的一条（改 XML，不是调 Word COM）。不实现多人协同引擎。

| 序号 | 项 | 状态 |
| --- | --- | --- |
| 1 | 文档：修订 id、与段落 id 的关系、`w:ins` / `w:del` / `w:rPrChange` | ✅ |
| 2 | inspect：默认不倒出全文修订；给 scope 才列出 | ✅ |

| 4 | 库测试与 Word 16.0 手测 | ✅ |

## 已锁定

- 真源仍是 XML。不要打开 Word 再 Save 来完成接受。
- 修订 id 按该故事里被收入节点的文档顺序：正文 `rev:{n}`，页眉页脚 `{容器}/rev:{n}`。`w:id` 只进 `xmlId`，不当全局唯一键（Word 拆 run 时会重复）。
- 本期收入：作为 `w:r` 祖先的 run 级 `w:ins` / `w:del`（直接子元素不是 `w:p` / `w:tbl`），以及 `w:rPrChange` / `w:pPrChange`。框内、注内、批注内不编。属性容器上的 `ins`/`del`（段落标记、表行）、块级包段落、`moveFrom`/`moveTo`、表上 `tblPrChange` 等不进树。
- `setParaText`：段内存在本期收入的修订节点时报 `NotImplemented`。不要只改 `w:t` 留下半残标记。
- 作者、日期取属性原文，缺则为 `null`。
- apply 只动被点名的那一个节点。同一 `w:id` 的多个节点是多条 `rev`。

## 不做

- 比较两份文档生成修订
- 修订气泡怎么画
- create 生成修订

## 前置

正文插删段落（接受插入等于留下新段）。

## 验收

另存带修订的样例能列出；接受删除后文字消失且无修复；拒绝插入后原文还在。
