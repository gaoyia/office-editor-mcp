# 契约陈旧条文普查

状态：❌ 未开始。
日期：2026-10-31

不在三种格式的待做表里，不占待做序号。只改文档，不动代码。

## 为什么要做

契约里写着「本期不做」或报 `NotImplemented` 的条文一共 184 处，是在不同时间写的。后来功能实现了，前面的旧说法有的没删。2026-10-31 抽查就找到 3 处：

- `docs/json-contract-docx.md` 第 236 行：「xlsx / pptx 本期不编 OLE」。xlsx 与 pptx 的契约里都有 `insertOle`。
- `docs/json-contract-docx.md` 的 `### deleteWatermark` 一节下面，混着一大段 xlsx 的 `setCell` 共享公式与数据表规则（约第 2340–2366 行）。其中「本期不读写数据表」「create 本期仍只写普通 `<f>`」两句，和 `json-contract-xlsx.md` 第 1578、1580 行矛盾。
- `docs/json-contract-xlsx.md` 第 421 行：「create 本期不写命名样式」。同一份契约第 1398 与 1702 行写着 create 可写 `workbook.cellStyles`。

文档是真源。真源里自相矛盾，模型和人都会照着旧说法用。

## 目标

四份契约里每一处「本期」「仍报 `NotImplemented`」「不支持」「不含……内」都和代码、`help` 一致。放错分册的段落搬回原处或删掉。

## 不做

- 不改代码，不改行为。发现文档写的比代码多（文档说支持、代码不支持），记下来另开缺陷，不在本份里补实现。

### 1. 已知 3 处

- 删掉 docx 契约第 236 行末那句关于 xlsx / pptx 的话。
- docx 契约 `### deleteWatermark` 下的 xlsx `setCell` 段落：xlsx 契约已有权威版本，直接删掉，必要时留一句链接。
- xlsx 契约第 421 行改成指向 create 一节，说明 create 能写 `workbook.cellStyles`。

### 2. 逐条核对

- 用脚本列出四份契约里所有「本期」「仍报 `NotImplemented`」「不支持」「本期不编」「不含……内」的行，结果存进本节。
- 每一条用代码或一条小测试确认还成立。成立的留下；不成立的删掉或改写；代码确实没做、但文档说做了的，记成缺陷。
- 一次改一份分册，改完跑一次 `python docs/json-schema/build.py`，确认生成的 schema 没有被意外改动。

### 3. 放错的段落

逐份分册检查：某格式的分册里出现另一种格式的 op 规则时，搬回所属的分册，或删掉，留链接。

### 4. schema

`docs/json-schema/src` 里 `limits` / `limitsEn` 提到的限制，与契约同步修改，然后重新生成 `request.schema.json`。
