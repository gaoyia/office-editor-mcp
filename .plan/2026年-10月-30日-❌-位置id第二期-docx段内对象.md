# 位置 id 第二期：docx 段内对象

状态：❌ 未开始。
日期：2026-10-30

不在三种格式的待做表里，不占待做序号。前置：「位置id第二期-机制与覆盖表」已完成。

## 范围

段落里、页眉页脚里、框内按出现顺序编号的对象：

- `bookmark:{n}`、`field:{n}`、`link:{n}`、`math:{n}`、`ruby:{n}`、`sdt:{n}`、`perm:{n}`、`rev:{n}`、`run:{n}`
- 没有 `docPr/@id` 或 `cNvPr/@id` 时的退路：`pic:index:{k}`、`txbx:index:{k}`、`cxn:index:{k}`、`shape:index:{k}`、`ink:index:{k}`、`chart:index:{k}`、`smartdiagram:index:{k}`、`ole:index:{k}`、`model3d:index:{k}`、`watermark:index:{k}`
- 以上各族在页眉页脚、框内、注内、批注内带容器前缀的形式

会让它们重排的 op：对应的 `insert*` / `delete*`，以及 `groupShapes`、`ungroup`、`deletePara`（连带删掉段内对象）、接受或拒绝修订（`rev:{n}`）。

## 不做

- 有内容编号的 id（`pic:{docPrId}`、`txbx:{docPrId}` 等）本来就不漂移，不动。
- 不改 `w14:paraId` 段落的规则。

### 1. 盘点

- 每一族写清楚：在哪个范围里计数（整篇、本段、本容器），由哪个函数查找。结果写回本节。
- 计数范围不同的族要分开编号，不要共用一个属性名。

### 2. 文档

`docs/json-contract-docx.md`「稳定 id」与各对象一节写明：

- 一次 apply 里，这些编号按 apply 开始时解释。
- 本批新建的对象不占旧编号；被删掉的再点名报 `IdNotFound`。
- 接受或拒绝修订之后，被收掉的 `rev:{n}` 再点名报 `IdNotFound`。

### 3. 实现

一族一族地接，每接一族跑一次 docx 测试。查找函数一律走通用机制，不再自己数位置。

### 4. 测试

- 每族一条「先删前面一个同族对象，再点名原来的第 n 个」：书签、域、链接、公式、拼音、内容控件、编辑区、修订、run。
- `:index:{k}` 退路每族一条，样本要去掉 `docPr/@id` 或 `cNvPr/@id`，用手写的 XML，不能只用本库 create 的产物。
- 框内与页眉页脚各挑两族做一条。

### 5. 手测

用 Word 16.0 打开「先删第一个书签、再改原来第三个书签」与「先删第一个公式、再改原来第二个公式」两份产物，改动落在预期的对象上，不报修复。
