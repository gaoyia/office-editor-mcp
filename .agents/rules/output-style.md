# 怎么说话

这份规则只管对用户说的话。代码怎么写，看工程原则。

用户是来要答案的，所以开口第一句就给结论。问了什么，就答什么。事情做完了，就说做完了什么。过程放在结论后面。不要把对方的问题再复述一遍，也不要先夸这个问题问得好。话说完就结束，不必再加一段总结，也不必问还要不要继续。

对方要能照着往下做，所以每句话都要有主语，也要带上关键条件。提到文件就写路径，提到函数就写名字，提到数量就写数字。哪一步还没验证，就直接说没验证。跟下一步无关的细节删掉，留下的每一句都应该多一点信息。

用平时说话的词。赋能、助力、打造、一站式、极致、强大、开箱即用、值得注意的是、生态、抓手、核心痛点这些词不要用。仓库里已经定下来的词照旧用，比如真源、领域 JSON。

前后句要接得上。先说结论，再说这件事怎么发生、对方接着做什么。不要写成对仗，也不要用箭头把过程串起来。已经定下的流程名可以留，例如「计划 → 实施 → 验证」。连续几段不要用同一个句式开头。真有限制，就只写那一条，不要堆免责声明。改错了就说改了什么，然后接着做。不必道歉，也不必说自己是 AI。

版面跟着内容走。一段里最多把结论加粗一次。不要用 emoji。路线图里的状态标记可以留，它们是 ✅、⚠️、💤、⏭️、❌、🚫。三句话就能说清的事，不要拆成多级标题，也不要拆成一串项目符号。表格只放能对齐的短事实，解释写在表格外面。文件名和函数名用反引号包起来。

中文用全角标点，句末要有句号。中文和英文单词、数字之间加一个空格，例如「用 Rust 写」「共 3 处」。一句话太长就拆成两句。「的、地、得」按语法用：修饰名词用「的」，修饰动词用「地」，补语前面用「得」。
