# XML 写回丢掉属性值里的换行与制表符

状态：❌ 未修复。修复切片见 `.plan/2026年-10月-30日-❌-属性值换行写成字符引用.md`
日期：2026-10-30
影响面：三种格式所有被改过（脏）的部件。没点名的属性也会被连带改坏。

## 怎么发现的

2026-10-30 第二轮代码审计逐行读 `crates/ooxp/src/xml.rs`。`write_element` 用 quick-xml 的 `BytesStart::push_attribute` 写属性，查了锁定版本 0.37.5 的 `escape`：只转义 `<`、`>`、`&`、`'`、`"`，不转义 TAB、LF、CR。

XML 1.0 §3.3.3 规定，读取方要把属性值里原样出现的 TAB、LF、CR 规整成空格。只有写成 `&#9;`、`&#10;`、`&#13;` 才能保住。

## 现象

用临时测试实测：

- 先在 `Sheet1` 上插一条数据验证，再把工作表 XML 里的 `prompt` 改成 `line1&#10;line2&#9;x`，模拟 Excel 存出来的文件。
- 对这份文件只发一条 `setCell`，改的是 `cell:Sheet1!B1`。
- 产物里的属性变成 `prompt="line1⏎line2⇥x"`，换行和制表符都成了原样字符。Excel 读到的提示是 `line1 line2 x`。

文件是合法 XML，Office 不会报错，所以只能靠查字节发现。

常见受害者：

- pptx、docx 图片和形状的替代文字 `descr`
- xlsx 数据验证的 `prompt`、`error`
- 任何带多行说明的属性

## 根因

`xml.rs` 的 `write_element` 把属性值原样交给 `push_attribute`，依赖 quick-xml 转义。解析时 `decode_and_unescape_value` 已经把 `&#10;` 还原成 LF，写回时没有再转成字符引用。

同一文件里给字符串拼 XML 用的 `escape_attr` 也只转义了四个字符，有同样的问题。文本节点里的 CR 也一样会被读取方规整掉。

## 修法（计划）

- `write_element` 写属性时自己转义：在 quick-xml 的五个字符之外，再把 TAB、LF、CR 写成字符引用。
- 文本节点里的 CR 写成 `&#13;`。
- `escape_attr`、`escape_text` 同步改。
- 先在 `docs/architecture.md` 的「元素树」一节写明这条写回规则。

## 教训

库里的保真测试都是「写出去，再用自己的解析器读回来比对」。quick-xml 读属性时不做规整，所以原样的 LF 读回来仍是 LF，测试永远是绿的。

这和 2026-09-25、2026-09-26 两份记录是同一条教训：拿自己的实现判自己的卷。凡是 XML 规范里读取方会做的规整（属性值、行尾、空白），回归测试必须直接断言写出的字节，不能只断言读回的值。

## 回归测试（计划）

- `xml.rs` 单测：解析 `<a x="1&#10;2&#9;3&#13;4"/>` 再写回，字节里必须是三个字符引用。
- xlsx 保真测试：带 `&#10;` 的数据验证提示，改同表另一格后，产物字节里仍是 `&#10;`。
- pptx 或 docx 各一条：带多行 `descr` 的图片，改同一宿主里的文字后，`descr` 字节不变。
